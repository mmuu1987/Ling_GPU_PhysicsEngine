## 生产接入与正确性

- 64KiB 的 int4[4096] 排序成员表，按 epoch / stance / 兵种守卫；最多 16384 个成员。六个 stance/type 专用核，global 排除已分区成员，不满足条件则退回原路径。
- 共用帧清理、快照、伤害结算与一次 swap/ack；逐核绑定 charge 数据。保留原墙体、切角、边界、局部导航掩码及射界检查。
- 原型差分 194 项是历史原型证据，不与生产测试混算，也不重复累计重跑次数。
- 当前类型掩码由 `UploadUnitTypeSettings` 同步。外部直接调用公开 buffer 的 SetData 绕过同步仍是需处理/约束的风险；混合类型保守掩码也可能派发实际为空的角色核，触发额外首次编译。
- 新增每个活跃通道 64KiB CPU 成员表及 64KiB shader 常量缓冲布局。现有 `LocalOrders.GpuBytes` 仅统计 ComputeBuffer，不含这部分；Unity 的实际常量缓冲实例/变体占用尚未做 VRAM 级计量，不能声称零额外显存。
