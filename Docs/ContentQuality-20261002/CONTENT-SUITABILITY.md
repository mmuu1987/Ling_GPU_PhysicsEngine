# 内容适配门禁：先适合兵团，再计入正式选择

适用：后续兵种引入与现有候选复核。**导入成功、VAT误差合格、测试通过、数量增加，都不能代替美术与角色适配。**

## 两层门禁

| 检查项 | 所需证据 | 不通过时 |
|---|---|---|
| 原件完整 | 查看原始模型的全部网格/子网格、部件与骨架；对照实际游戏完整LOD。不只读统计回执 | 先定位遗漏；不得用不完整模型继续当正式候选 |
| 体态与轮廓 | 正面、常用三分之四视角、侧面可辨识主体；体态和关节/武器能解释其地面、骑乘或现有远程角色 | 留在实验资源，不以增加特殊飞行/技能勉强合理化 |
| 动作语义 | 实际游戏待机、移动、攻击、死亡的多个时刻；移动不像无意义滑动、出手与攻击方式相符、死亡状态可分辨 | 记录具体问题，保持候选状态；不能仅用“像素在动”签收 |
| 材质与辨识 | 使用实际游戏网格、VAT、材质和贴图；无错误着色器、明显丢贴图/部件，普通战场距离仍能区分 | 技术故障先修；风格/辨识不合适则暂缓正式引入 |
| 角色明确 | 用一句话说明其现有行为与兵团用途，体型与导航/攻击方式一致 | 不为凑数量接入 |
| 预览诚实 | 真实配置的全身静态图；固定光照/视角、等比、留完整轮廓；不能拿AI概念图替代 | 正式候选不能用空白或虚构头像 |

**技术层**可以自动拒绝空图、错误shader、边缘截断、缺四动作/无可检测动作、无真实预览等问题。
**内容层**仍需查看轮廓、动作语义与角色；技术层全绿不自动产生“美术合格”或“玩家认可”。

本轮用户暂停人工试玩。代理的画面复核、内部回调/布局验证与独立程序冒烟必须分开记录，不能填成人工键鼠、平衡或V1放行。

## 当前处理决定

- `roster-platformer-enemy` / `troops6-enemy`：原件就是绿皮头部主导造型；退出新的正式选择。
- `roster-platformer-skull` / `troops6-skull`：原件就是骷髅头造型；退出新的正式选择。
- 两者不是被转换流程漏掉身体。源FBX所有三角形与现有游戏Full-LOD计数相同，原件/游戏真实图已对照。原件图是原几何+源纯色的中性无光照记录，不冒充原作者材质shader独立验收。
- `roster-platformer-crab`：有可读的低矮主体、肢体与咬击表现，保留现有近战候选；不新增技能，不宣称完成深度平衡或真人接受度。
- 其他既有内容补真实图与常见视角/四动作技术证据；不因此统一标为已获人工认可。

## 非破坏性兼容

- Version01–06、已有包、模型/材质/原FBX不改写、不重烘、不删除。
- Version07保留全部旧战场ID、模板ID、revision、原配置引用、地形/战场内容身份。
- `hiddenFromSelection`只过滤正式卡片、兵种库与新单位选择；`TryResolve`/`TryResolveTemplate`不按可见性拒绝旧身份。
- 为旧方案兼容，隐藏条目的场景与资源仍包含在新构建中。旧方案中的单位不会被静默删除或替换。
- 缺少新元数据的历史目录保持默认可见；不修改其序列化资源。

## 下一批的入库顺序

原件与许可证据 → 原件完整性/轮廓适配 → 实际游戏材质和四动作 → 角色说明与常见视角复核 → 真实预览 → 内容决定 → 新编号版本/必要回归。

未通过内容复核时先保留在候选/实验区，**不要先公开，再拿数量或技术成功当选择理由**。本轮之后仍暂停进一步扩充，先处理复核中发现的具体问题。
