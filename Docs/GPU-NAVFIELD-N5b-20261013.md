# 导航 C · N5b 报告：全军命令改用"阵线目标"（2026-10-13）

## 结论

- **全军点命令（移动/撤退等）现在可以走"阵线目标"**：GPU 场的目标不再是一个格子，而是一条垂直于前进方向的线段。开关 `RuntimeFlowConfig.gpuNavFormationLine`，**默认关闭**（需要同时开着 `gpuNavField` + `gpuNavSteering`）。旧的点目标路径一行没删。
- **平原实测**（1 万人向西移动 200 m，各 1 次）：
  - 点目标：挤成约 76 × 76 m 的圆团；
  - 阵线：到达后排成 **182 m 宽、34 m 深**的横队，宽度与出发时的阵宽（177 m）一致；
  - 方阵中心离点击位置 **5.4 m**（点目标时差 11.9 m 没走到）。
- **森林山口实测**（与 N4 定版同设置，120 秒，各 1 次）：卡住人数 993 → **581（−41%）**，越过山脊 480 → **555**，中位距离 167 → **152 m**。
- 帧时间不变（平原 11.82 → 11.77 ms，山口 12.80 → 12.69 ms）。
- 编译 0 错误 0 警告；过滤测试 **158/158 通过**（新增 4 个 N5b 测试；图距离下 GPU 与 CPU 逐位一致）。

## 实测数据

**平原**（plains-1024，2 万单位，第 0 队向远离敌军方向移动 200 m，150 秒）

| 指标 | 点目标 | 阵线（初版） | 阵线（定版） |
|---|---|---|---|
| 正面宽度（5%–95%） | 75.6 m | 181.8 m | **181.8 m** |
| 纵深（5%–95%） | 75.7 m | 34.8 m | **34.4 m** |
| 重心沿前进方向偏移 | −11.9 m | +29.2 m | **+5.4 m** |
| 每 2 m 格最多 / 95 分位人数 | 8 / 7 | 8 / 7 | 8 / 7 |
| 平均帧时间 | 11.82 ms | 11.82 ms | 11.77 ms |

- 初版按"当前纵深的一半"放置阵线，但到达后队伍被压得更密，结果越过目标 29 m。定版改为**按人数估算到达后的纵深**：纵深 = 人数 × 每人占地 ÷ 正面宽度。每人占地取实测值 0.6 m²（点目标约 0.58，阵线约 0.64），做成配置项 `gpuNavLinePackingArea`。
- 拥挤程度（每格人数）没有改善，这是后排持续往前压造成的，属于 N5c（拥堵等待）要解决的问题。

|---|---|---|
| 越过山脊人数 | 480 | **555** |
| 卡住人数 | 993 | **581** |
| 距目标中位距离 | 167.2 m | **152.4 m** |
| 仍在移动的人数 | 8890 | 9344 |
| 平均帧时间 | 12.80 ms | 12.69 ms |

截图上，阵线版的队伍接近山口时保持着更宽的正面，点目标版更早收窄成一路纵队。

**说明**
- 每种都只跑了 1 次；山口和平原场景没有交战，不像追击场景那样有双峰波动。建议您在 Editor 里亲眼看一下。
- 阵线版两次都出现过一次约 430 ms 的单帧尖峰。已确认是**探针自己的诊断**：下令后它会在主线程上算一遍 512² 的精确解（日志 `dijkstraMs=322`）。游戏本身没有这个开销。
- "轴对齐朝向"指标在平原阵线版里偏高（约 0.5）。这是因为全军笔直向正西走，正西本身就是 45° 的倍数，被计入了，不是方向条纹。这个指标在这种场景下不适用。

## 规则

- 只在全军点命令**下达或改变时**计算一次阵线，同一命令内不随行军重算（不会反复重算种子）。
- 数据来源是现有的队伍遥测（GPU 归约后每 0.5 秒异步回读的重心与包围盒），没有新增 GPU 归约。
- **方向** = 目标 − 当时的重心。
- **宽度** = 军队当前垂直于前进方向的宽度，限制在 8–400 m（`gpuNavLineMinWidth` / `gpuNavLineMaxWidth`）。
- **位置**：中心在目标前方"估算纵深的一半"处，最多 60 m（`gpuNavLineMaxOffset`）。
- **贴合地形**：从目标点出发逐格向前、向两侧延伸，遇到第一个不可走的格子就截断，所以阵线连续、而且能沿直线到达目标，不会跨墙、跨山脊。
- **退回点目标**的情况：遥测约 1 秒内都无效，或者军队已经站在目标上（没有方向）。
- 着色器：阵线队伍不再在 8 m 内把兵交还 CPU 点流场，**到阵线即停**（按原有停止半径）。
- 拥挤代价（N4）同样作用于阵线目标。
- GPU 与 CPU 用同一份**格子位掩码**判断目标格，保证结果一致（每队 32 KB，只在目标变化时上传）。

## 改了哪些文件

- 新增 `Assets/MassEngine/FlowField/GpuNavField.Line.cs`：阵线的生成、缓存和位掩码上传。
- `GpuNavFieldGraph.cs`：新目标模式 `Line`，参考实现支持位掩码。
- `GpuNavFieldSeed.cs`：种子支持阵线目标。
- `GpuNavField.compute`：`NAV_GOAL_LINE`（读 `_NavGoalBits`）。
- `GpuNavField.cs`：解析目标时接入阵线，采样时绑定 `_GpuNavLineMask`，拥挤代价覆盖阵线。
- `AgentDataCommon.hlsl`（`patch_n5b.py`）：`_GpuNavLineMask`，阵线队伍跳过点交接。
- `RuntimeFlowConfig.cs`（`patch_n5b_cs.py`、`patch_n5b_cs2.py`）：新增 5 个字段，开关默认 false。
- `MassEngineManager.GpuNavField.cs`：每帧同步配置，并提供遥测。
- `GpuNavFieldTests.cs`：新增 4 个测试：
  - GPU 与 CPU 一致、种子是不动点（图距离 / Eikonal）；
  - 几何：垂直于前进方向、放在目标前方、斜向时仍贴在线上、偏移有上限、遇墙截断、无方向时不建阵线；
  - 同一命令只算一次，没有遥测时退回点目标，开关关闭即点目标。
- 探针 `NavBaselineProbe.cs`：新参数 `line`、`moveAway`，新增结束时的队形指标。
- 远程备份在 `outputs/Round6/n5b_bak`。

## 已知限制（不在本阶段处理）

- 后排持续往前压，到达后每格人数没有下降 → **N5c**。
- 宽度用的是包围盒在垂直方向上的投影。如果出发时队伍已经拉成长蛇，正面会偏窄。
- 多航点路线是按"重心离航点 8 m 以内"判断到达的。阵线版重心偏移 5 m，在这个范围内，但大军团、窄地形下可能仍有偏差。
