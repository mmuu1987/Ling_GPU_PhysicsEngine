## 1. 总体安排与开工边界

本次不是把三项改动一次塞进工程，而是按 **基线保护 → 半径与拥挤 → 部署拖拽 → 局部指挥 → 集成验收** 推进。

基本原则：

1. 每一阶段先写清契约和测试，再实施最小改动，最后核对证据。
2. 半径、部署、局部指挥三大阶段分别验收；一项未通过，不以继续堆功能掩盖问题。
3. 局部指挥先验证底层能真正分开控制，再做完整操作界面，避免“框选成功，但整军团一起动”。
4. 每个大阶段交付结果后暂停，向用户汇报，通过后再推进下一大阶段。局部指挥底层原型另外设独立检查点。
5. **最初 v1 规划轮次只获规划授权；后续用户已按阶段授权推进至 P8。授权继续开发不等于真人验收通过，也不自动授权后续阶段或出包。**
6. 新手引导继续暂缓，不自动恢复；不扩地图、人数、兵种、联盟或永久编队。

### 已确认的交互基线

- 先选择军团，框选只筛选当前军团内存活士兵。
- 局部命令只改变被选成员，未选成员保留原命令。
- 攻击先沿用现有主动接敌，不另加点名集火。
- 待命停止主动行军与追击，允许近距离自卫及必要避让，不是完全停火。
- 地图色块按当前编成操作，不默认把同军团所有编成一起移动／缩放。
- 拖拽改变位置、占地、密度与宽深比，不改变人数和模型大小。
- 图鉴半径接通已有真实参数，预览显示相应范围，不做只有显示没有生效的滑块。

### 不在本轮范围

新教学关、全新战斗模式、战中复杂阵型保持、快捷编队保存、联盟系统、地图编辑器、任意大规模压力测试、全面美术重做。现有整军团高级操作应保留，但不默认扩展为局部小队的全部高级能力。

## 4. A 阶段：角色半径与拥挤

### P1：只读显示与真实尺度圆环

#### 任务

1. 整理半径来源链：`FlockingConfig.agentRadius → GPU settings → 各使用路径`。
2. 核对单位生成时的水平缩放、模型资源是否已烘焙尺寸、地面锚点与预览比例。
3. 区分基准半径与有效世界半径。若采用 `基准半径 × 最大水平缩放` 约定，必须列出已有调用方，防止某些路径再次乘缩放；不能未经核对直接全局替换公式。
4. 在图鉴新增只读半径、直径和来源展示，暂不改变保存格式或战斗参数。
5. 在独立模型预览中增加圆环；圆心来自单位实际锚点，不使用模型包围盒中心代替。
6. 圆环与模型处于同一坐标和相机空间，随旋转、缩放保持比例；默认取景可容纳两者。
7. 现有地面阴影继续作为阴影，圆环使用独立语义及绘制资源；不修改官方角色材质或所有 VAT 模型着色器。
8. 内嵌与放大预览一致，切换兵种和反复关闭窗口时释放新建资源。

#### 重点模块

`WarSandboxFrontEnd.UnitLibrary.cs`、`WarSandboxFrontEnd.UnitPreview.cs`、`UnitModelPreviewRenderer.cs`、`UnitModelPreviewWidget.cs`、`FlockingConfig.cs`、GPU 参数构建与半径读取路径。最终改动清单先记录再执行。

#### 验收

- 圆环尺度可由已知半径、世界长度标尺和相机投影核对，不只是“看着差不多”。
- 对称／非对称模型、较小／较大体型、非 1 水平缩放样本均检查。
- 半径显示不因模型长剑、翅膀或阴影大小发生错误变化。
- P1 不改变任何战斗半径、模型缩放、兵种数据或用户保存文件。
- 反复开关预览不持续累积 RenderTexture、Mesh、Material、ComputeBuffer。

#### 交付与回退

提交来源映射表、预览截图和无行为变化证据。若显示尺度尚未统一，不进入可编辑阶段。回退仅移除新增显示与绘制，不触动原始单位配置。

### P2：编辑、保存、覆盖与运行时生效

#### 任务

1. 为半径增加稳定字段键；保留既有键名及枚举／数组索引关系，不插入导致旧字段错位的位置。
2. 扩展现有字段定义／读取写入链，使其能处理 FlockingConfig，而非误借攻击距离等字段。
3. 采用待编辑 → 预览 → 明确保存全局的现有交互，预览立即读取待编辑值。
4. 保存仍按模板 ID 生效，提示相同模型的其他模板不自动同步。
5. 保持 `局部覆盖 > 全局覆盖 > 官方值`；若方案有局部半径覆盖，应显示真正的有效值及来源。
6. 运行时复制需要修改的群体配置，不直接修改共享源资产；未修改的兵种保持旧路径。
7. 在新进入战场／明确应用布阵的既有边界解析和上传有效配置，不在正在运行的战斗中偷偷改变实体半径。
8. 旧文件缺少新字段时回退官方值；非法、非有限或超限输入明确拒绝／提示，具体边界以 P1 的使用链与空间查询能力为依据。
9. 修改半径后重新校验实际布阵占地与密度；不自动减人数或改其他参数替玩家“修好”。
10. 不自动把所有已保存方案重写为新格式；写入失败保留原文件，取消编辑不落盘。

#### 核对事项

现有地形清距有跨重置保留较大半径的策略。必须验证调大后恢复默认、重置本局、重新进入场景各自何时生效，避免图鉴已恢复但通路仍被旧清距封住。需要改变缓存策略时单独记录理由和回归范围。

#### 验收

- 改值、预览、保存、重新进入战场后 GPU 实际参数一致。
- 取消、恢复官方、局部覆盖、无覆盖、旧文件、写入失败均有测试。
- 只修改指定模板，其他模板及原始 .asset 哈希不变。
- 半径变化不改变模型大小、伤害、军团归属或人数。
- 修改前后均验证进入战场、返回、再战和重新载入。

#### 交付与回退

字段兼容说明、隔离保存样本、值链核对日志和恢复测试。回退不删除用户文件；保留新字段数据副本，不用旧版本重新保存并悄悄丢弃用户改动。

### P3：复现拥挤，按证据定向修复

#### 任务

1. 在固定镜头、人数、密度下分别观察初始静止、行军、接敌。
2. 记录实际半径、缩放、中心间距、分离触发范围及可见穿插；先判断问题出在哪一阶段。
3. 专项核对已有接触分离按缩放计算、另一段分离直接读取配置半径的差异。确认设计约定后再决定是否统一，不能只凭代码差异断言是根因。
4. 根据证据选择最小修复：具体模板半径、初始间距、缩放单位不一致、目标汇聚或分离规则。禁止同时大幅改多组参数后无法归因。
5. 半径调整需连带验证近战攻击距离、交战站位、窄路清距、邻域查询范围、弹道相关读取和动态拥堵。
6. 如果根因属于后续局部命令的到达目标聚集，记录依赖并在 C 阶段修，不用提前乱改所有兵种补偿。

#### 验收

- 有可重复的修复前后对照，不靠单帧远景截图宣称解决。
- 初始没有明显重叠爆开；行军和接敌的穿插／抖动有可观察改善。
- 没有以放大到无法通过窄路、近战永远够不到目标为代价。
- 性能对照记录齐全；保留默认配置与正常大小兵种的回归。
- 如果无法确认根因，明确“仍待定位”，不把半径滑块完成当成拥挤修复完成。

### A 阶段检查点

交付：可视化、编辑生效链、拥挤问题结论及修复证据。请用户重点检查模型圈是否直观、指定小角色是否更清楚。通过后再进入部署拖拽。

## 5. B 阶段：部署地图直接拖拽

### P4：只做平移，先不做缩放

#### 输入与数据模型

采用统一拖拽会话：`空闲 → 按下候选 → 超过阈值开始拖动 → 临时预览 → 松手提交／取消回退`。

会话记录：目标编成身份、原始草稿版本、原始位置、抓取偏移、地图投影、当前预览位置。不能仅记 Draft 列表下标；列表变动后不得拖错对象。

#### 任务

1. 在地图色块上按下左键确定对象，短点击仍为选择。
2. 超过阈值后拖动，保持抓取点相对色块的偏移，不把中心瞬间吸到鼠标。
3. 使用实际地图内容区域与世界 X/Z 投影；侧栏展开导致地图布局变化时先稳定布局或取消会话，不能跳位。
4. 拖动每帧只更新轻量预览，不每帧写正式草稿、不每帧重建 GPU 部署、不堆撤销记录。
5. 对完整编成占地做校验，而不是只看中心点。
6. 合法松手写一次草稿；非法松手恢复原位置并显示原因。
7. Esc、失焦、切换页面／编成、打开模态框时清理会话；规定离开地图区域的取消行为。
8. 旧点击放置与拖动互斥，松手不额外触发一次点击放置。
9. 未提交数值输入先明确校验，失败时不覆盖输入文本。
10. 鼠标行为仅作用战前草稿，不直接发战斗移动命令。

#### 验收

人数、密度、比例不变；单次撤销恢复原位置；拖出边界／穿障碍／不可通行区域不提交；多编成只动当前色块；点击、拖动、取消和切页不串输入。真实开战位置与地图一致。

### P5：尺寸手柄与参数联动

#### 固定数学契约

- `面积 = 正面宽 W × 纵深 D`
- `密度 = 人数 N / (W × D)`
- `宽深比 = W / D`
- 当前世界 X 对应纵深 D，Z 对应正面宽 W；不得把屏幕宽高直接当作 W/D。
- 固定人数，不缩放士兵模型。

#### 任务

1. 选中编成后显示边／角手柄，命中区略大于视觉线条，小色块也能操作。
2. 拖单边改变对应轴，对侧边固定；拖角改变两轴，对角固定；Shift 可锁宽深比。
3. 鼠标跨过对侧边时限于最小合法尺寸，不产生负面积或突然翻转。
4. 中心位置随锚定边规则正确变化，右侧位置、密度、比例同步预览。
5. 数值输入与鼠标操作共用一套转换／校验函数，避免两套公式漂移。
6. 自动占地与手工占地明确转换：旧手工数据在未编辑前不擅自改写；编辑后只能有一个权威来源。
7. 参数限制反映到实际手柄位置，不能视觉矩形已经变化而数值被静默钳制成另一套形状。
8. 基于 P1/P2 的有效半径、真实生成行列、抖动和间距检查能否排下。简单面积公式只作初筛，不替代实际排布校验。
9. 沿用已有同队／敌对重叠规则；不顺带禁止原来合法的同队混编。
10. 一次尺寸拖动是一条可撤销修改，只有合法松手才提交；不自动保存方案。

#### 验收

- 单边、四角、等比例、极小／极大尺寸、反向拖动均正常。
- 地图尺寸 → 数值 → 实际生成占地闭环一致，在预先约定的浮点容差内通过。
- 截图参数样例 1,024 人、密度 0.4、比例 2.2 的推导可复核。
- 拖动改变密度／比例，不改变人数／模型体积；缩到不能容纳实际单位时拒绝。
- 撤销／重做、载入旧方案、手工占地、改人数后再拖拽不失真。
- 720p／1080p 的侧栏、输入框、手柄和地图显示均不穿透／错位。

### B 阶段检查点

交付：真人拖动录像、数学／校验测试、撤销及方案兼容证据。请用户重点体验抓取是否跟手、缩放是否直观。通过后再进入局部指挥底层。

## 6. C 阶段：局部指挥与框选

### 6.1 必须先锁定的概念

| 概念 | 负责什么 | 不负责什么 |
|---|---|---|
| 军团／teamId | 归属、敌我、统计、胜负、既有整军团行为 | 不能拿来假装临时小队 |
| 当前选区 | 玩家现在选中的成员 | 不能直接充当所有历史命令的成员列表 |
| 命令成员快照 | 某次命令实际接受者 | 不随之后的框选改变 |
| 指令组／导航通道 | 共用目标、姿态与寻路资源的成员 | 不增加新的阵营或永久编队玩法 |
| 本局代次 | 区分重置、再战前后的实体与回读结果 | 不允许旧结果复用到新一局 |

建议新增职责拆分：选择服务、命令作用域分发器、局部命令／导航管理器、GPU 选择掩码与选中环渲染。名称在实施设计时确定，不先创建空壳文件。

### P6：先用固定成员证明底层能独立指挥

#### 首个原型用例

同军团划出 A、B 两批明确成员；A 去左侧，B 去右侧，未分配成员保持原命令。随后只把 A 改为待命，B 仍继续前往原目标。

先通过这个用例，再接鼠标框选。原型中不提供会误导用户的正式入口。

#### 核心任务

1. 梳理现有主链：玩家入口 → ArmyOrder／BattleController → team 导航覆盖 → 流场 → GPU 移动、索敌及姿态。
2. 确定 per-agent 命令覆盖数据；优先使用独立缓冲，不随意改变既有 AgentData 的 64 字节布局及 VAT 消费约定。
3. 不改 teamId。为命令组建立独立导航上下文，避免多个局部目标仍写进同一个团队目标槽。
4. 未设置局部覆盖的单位走原整军团路径；有覆盖时移动、姿态、索敌和停止条件都读取该成员的有效命令。
5. 共享不变的地形／导航数据，对有独立目标的组分配必要的流场资源。不每兵一张流场，不用纯直线追点绕过障碍。
6. 测量 FlowCellCount、每槽资源、更新成本后确定并发指令组预算。超预算明确拒绝新独立命令并保留旧状态，不偷偷合并或覆盖另一组。
7. 校验当前选中成员的实际可达性与有效半径，不能误用“全军团所有编成必须连通”而挡住合法局部命令，也不能只查出生点。
8. 命令替换采用“先校验与预留资源，再一次提交”的事务方式；失败不能先清掉旧命令。
9. 同一成员被新命令覆盖时，只从旧组移除相应成员；旧组剩余成员继续执行。
10. 空组资源回收、GPU 尚在消费的旧句柄和代次管理明确；防止回收后同槽复用串命令。
11. 目标采用有空间分布的临时到达位置，不让所有成员抢一个点；不扩展完整战中阵型保持。
12. 整军团新命令应明确覆盖该军团成员的局部命令；仅切换当前军团或选择范围，不清除已发命令。

#### API 契约内容（拟定，不是已实现接口）

输入至少可追踪：本局代次、命令序号、军团 ID、成员快照／版本、命令类型、目标与合法性结果。输出能区分：拒绝、已提交、实际接受；不能因 CPU 排队成功就假报 GPU 已执行。

#### 验收

- 两组异向移动可重复，互不覆盖；其他成员的命令／路线／策略不变。
- 混合兵种、障碍、不可达目标、空组、成员死亡、重置、组预算耗尽均安全。
- 整军团模式仍工作；新通道关闭或无局部覆盖时，不出现明显性能或行为回退。
- 敌我、伤害、人数统计、占点和胜负不因分组而改变。
- 有原型报告、资源预算和性能实测。未通过时停止，不先堆框选界面掩盖底层问题。

### P7：军团内框选与可视反馈

#### 输入规则

- 当前军团决定候选范围；没有明确军团时提示先选择。
- 战场非 UI 区域左键拖动产生矩形；首版以存活士兵地面中心的屏幕投影入框为准，剔除镜头后方。
- 遮挡规则明确且一致；首版按投影选取，不额外为每兵做昂贵射线或生成 Collider。
- 框选替换旧选区；框空进入零选中并禁用局部命令，绝不隐式全军指挥。
- 切换军团清除旧局部选区并清晰显示新范围；已发命令保持。

#### 任务

1. 捕获松手时的相机矩阵、视口及选框，避免相机移动后套用不同投影。
2. GPU 侧过滤军团、存活与投影，生成选择掩码；按需要异步回读计数，不每帧同步拉回所有 agent 数据。
3. 选择结果带本局代次、军团 ID、请求序号；丢弃切换军团／重开／新框选之后返回的旧结果。
4. 结果尚未确认时显示真实状态，不让下一条命令错误使用旧选区。
5. 验证实体索引在本局是否稳定；若有重排，增加明确映射，不凭假设把可见实例序号当实体 ID。
6. 使用批量绘制的选中环，不创建大量独立 GameObject。死亡成员从有效选择中剔除。
7. 显示“当前军团 · 已选 N / 存活 M”，区分整军团范围、局部范围、零选中。
8. 多成员正执行不同命令时显示“混合命令”，不伪称整个军团都在执行同一个目标。
9. 统一鼠标状态优先级：模态／UI → 部署编辑（若打开）→ 战场目标选点 → 框选／选择；互斥处理镜头输入。
10. 切页、失焦、打开帮助、退出、再战时释放捕获并失效旧请求，遵守原有暂停与模态规则。
11. P8 的入口作用域尚未接通时，选择预览只在开发验证流程启用；禁止带着局部选区继续走旧整军团按钮／热键／小地图命令，不能把半成品入口开放给普通试玩。

#### 验收

交错双方、同军团多编成、密集部队、空框、快速连框、切军团、镜头变化、死亡和再战均无错选；UI 不穿透；显示数量与实际命令快照一致；没有逐帧全量同步 GPU 回读。

### P8：四类命令与全部玩家入口

#### 动作契约

- **移动**：选中成员前往有效区域，保持现有移动与交战语义；本轮不暗改为另一种攻击移动。
- **攻击**：选中成员主动接敌，未选成员不被解除待命或改目标；不新增点名集火。
- **撤退**：选中成员撤向所属军团既有出生／后方锚点，并校验到达区域；未选成员保留原命令。
- **待命**：停止主动行军和追击，保留分离／避让、近距离自卫；不冻结动画、战斗冷却或整个模拟。

#### 入口统一

按钮、键盘快捷键、小地图下令等玩家入口必须经过同一作用域解析。不能按钮支持局部、快捷键仍控制整军团。

首版局部移动先以单目标为范围。整军团已有航点操作不删除；局部范围内未支持的高级操作必须明确提示／阻止，不能偷偷回落成整军团命令。需要局部航点时另行确认范围。

直接用于测试的显式整军团 API 保持其原含义，不因 UI 恰好有选区而改变调用语义。

#### 状态处理

- 暂停时下令的恢复行为先遵守已存在且经 P0 记录的规则，不另造一套教学式自动暂停。
- 仅选择、打开统计和查看信息不下令。
- 原命令在取消选择、关闭帮助和查看菜单后继续有效，除非原有流程明确要求结束／重置。
- 胜负后不接受新战斗命令；返回布阵、再战、换场景清理选择、组状态、导航资源和异步回读。
- 错误反馈说明原因和“旧命令保留”，不出现部分成员已改、部分成员拒绝但界面报全成功。

#### 验收

每种命令都验证“选中改变、未选不改”；至少覆盖相反方向、混合命令、重叠选区、撤退与再攻击、待命自卫、目标拒绝、暂停恢复、结算再战，以及全部玩家入口。

### C 阶段检查点

交付：实际框选与四命令录像、GPU 成员／组状态对照、性能报告、异常与资源释放测试。请用户验收“指哪批，哪批动”，不是只检查选框长得对不对。

## 7. P9：三项联合回归与交付

### 7.1 端到端流程

1. 图鉴修改指定模板半径，预览对应变化，取消与保存各试一次。
2. 重新进入战场，核对实际生效值及模板 ID。
3. 拖动一个编成，调整尺寸；检查密度、比例、合法性和撤销。
4. 保存隔离方案，退出重载，核对位置／尺寸／半径覆盖。
5. 开战，选择军团，再框选部分士兵。
6. 下达移动、攻击、撤退、待命，验证未选成员保持原命令。
7. 检查拥挤与间距，不因局部移动目标重新形成无法解释的堆叠。
8. 运行到自然结算，再战并重复关键操作；不能通过强制结算替代自然结算验证。
9. 换正式场景复核引用、地形和图形，没有旧状态残留。

### 7.2 自动测试与真人测试分工

| 层级 | 验证内容 | 不可以替代什么 |
|---|---|---|
| EditMode／纯数据 | 公式、字段解析、覆盖顺序、保存兼容、撤销事务、状态机 | 不替代 GPU 行为或鼠标手感 |
| GPU／运行时 | 成员过滤、局部命令、导航、资源代次、死亡／再战、真实参数 | 不等于物理鼠标输入验收 |
| 真人鼠标 | 框选、拖拽、缩放、取消、快捷键、窗口布局与反馈 | 不替代全量成员和数值断言 |
| EXE 候选 | 发布环境、实际键鼠、正常对局、加载／保存、异常日志 | 不以 Editor 成功替代独立运行 |

### 7.3 性能测量与停止线

固定设备、场景、人数、镜头与设置，预热后重复测量，记录 CPU/GPU 中位帧耗、P95、GC、内存／显存和选择到反馈的延迟。

P0 后锁定正式预算。规划阶段的初步调查线：

- 不使用新功能时，额外帧耗超过基线约 5% 或测量噪声容差，需要专项解释和复测，不能无记录放过。
- 框选反馈以约 100ms 量级为体验目标，记录真实延迟分布；不能靠显示旧选区伪造即时响应。
- 稳态输入路径不引入持续 GC 分配，不引入逐帧全量同步 GPU 回读。
- 来回进入战场、切预览和重开若出现持续资源增长，直接视为未通过。

以上是待基线校准的工程目标，不是已经测得的成绩或无条件性能承诺。默认 2,048 人必须验收，不自动用十万人压力测试扩大本轮范围。

### 7.4 候选包规则

- 出包前向用户确认，不因写完某个阶段就自动生成一堆版本。
- 37 包保持原样。候选用新目录，版本号与名称届时确定，不冒充已经交付的“38”。
- 以当前正式场景和当前源码构建，不盲目重跑依赖旧目录／旧包的历史构建脚本。
- 当前源码中原本未入 37 的非法坐标防护应列入候选差异并重新回归，不冒称本轮新写。
- 独立 EXE 验收通过后才更新现役交付索引；正式切换还需用户确认。
- 未通过的候选明确标记，不覆盖现役，不自动删除用户其他构建。

## 9. 风险、停工条件与回退

| 风险 | 预防／处置 |
|---|---|
| 半径圈只是视觉正确，战场仍旧值 | 核对有效模板 ID、覆盖层与 GPU 参数，不只检查 UI |
| 半径增大导致过不去／打不到 | 同时验地形、近战、查询范围，不批量改所有兵种 |
| 拖动大量写草稿或重建部署 | 临时预览，合法松手一次提交 |
| 错把矩形屏幕宽高当战术宽深 | 共用 X/Z 转换和往返测试 |
| 框选后整队目标被修改 | 独立命令／导航通道，未选成员状态断言 |
| 更换选区使旧命令失效 | 当前选区与命令成员快照分离 |
| GPU 异步结果串军团／串局 | 军团、请求序号、本局代次联合验证 |
| 新导航组无限吃显存 | 经测量的预算、回收、安全拒绝，不每兵一场 |
| 按钮正确但热键／小地图仍整队下令 | 统一命令分发，覆盖全部玩家入口 |
