# 交互完善：需求理解与解决方案

日期：2026-10-07  
状态：**需求理解已获用户确认；实现尚未开始。**

详细分阶段安排见 [实施方案](IMPLEMENTATION.md)。本次用户仅要求规划，未启动代码修改。

## 0. 本轮边界与结论

用户决定：新手引导暂缓，先补齐既有操作体验，不扩展新的玩法系统。新手引导建议已独立存档：[ONBOARDING-DEFERRED.md](ONBOARDING-DEFERRED.md)。

本轮三项需求：

1. 先选军团，再在战场框选该军团的一部分士兵，只对这些士兵下达移动、攻击、撤退、待命。
2. 在战前部署地图上直接拖动编成色块、拖边框改变占地，让位置、密度、宽深比联动。
3. 在兵种图鉴暴露角色占地半径，模型预览显示真实半径圈，并据此排查小角色拥挤问题。

统一目标：**点谁能看清、命令作用谁能看清、布阵和身体占地能看清。**

初步建议实施顺序：半径显示与诊断 → 地图拖拽 → 局部指挥。理由是先建立正确的空间尺度，再完善布阵，最后接入改动较深的命令与导航链路。顺序是建议，不是已批准的执行指令。

本轮只阅读源码并编写文档；未改 Assets、引擎、场景、配置或现役 37 包，未运行 Unity／构建／Git 提交。

## 1. 基于当前实现的判断

| 事项 | 已核对的实现 | 影响 |
|---|---|---|
| 命令作用范围 | BattleController / Manager 的主命令、导航覆盖和流场目标按 teamId 组织；GPU 主流场按 team 分区 | 框选不能只做 UI，必须真正隔离被选成员的命令与导航 |
| 部署色块 | 地图遍历 Draft 的每个 entry 绘制，色块选择对应一个编成；当前以点击放置为主 | 一个军团可能有多个色块，不能把每块误当成整个军团 |
| 阵型占地 | SpawnConfig 从人数、密度、宽深比推导矩形；支持会覆盖自动推导的手工占地 | 拖动尺寸必须和数值使用同一数据来源 |
| 半径 | FlockingConfig.agentRadius 已存在，并写入 GPU settings；图鉴可调字段尚未包含它 | 不必新造一份无关的视觉半径，需接通已有参数 |
| 预览 | UnitModelPreviewRenderer 有独立 VAT 模型预览；现有地面阴影半径来自模型包围盒的视觉估计 | 阴影不能冒充物理／占地半径圈 |
| 保存 | 图鉴采用待编辑、保存全局、下次进战场生效的流程，按模板 ID 区分 | 半径应沿用保存边界与模板作用域，不直接改原始资源 |

截图能确认部署交互和当前参数，但没有士兵近景或运动过程，不能仅凭该图确认拥挤的根因。

## 2. 军团内框选与局部指挥

### 2.1 对用户需求的理解

选择军团决定“可以选哪些士兵”；框选决定“本次命令给其中哪些士兵”。框选不改变军团归属，不创建敌我关系，也不要求把框出的士兵另存成军团。

例如：当前攻方有 1,024 人，框出其中 120 人后，移动按钮只向这 120 人发令；其他 904 人保留原有命令。红蓝双方同时进入框内时，只筛选当前军团的存活成员。

这里“其他士兵不受影响”指命令、路线和导航策略不被误改，不是保证物理位置完全不动；正常避让、碰撞、受击仍会发生。

### 2.2 建议的最小交互契约

- 必须存在明确的当前军团，没有则提示先选择军团。
- 在 3D 战场非 UI 区域按住左键拖动；按下与拖动使用小阈值区分，避免点击被误判为框选。
- 首版建议以士兵地面中心的屏幕投影落入矩形为准，剔除镜头后方、死亡、其他军团成员；遮挡选择规则统一说明，不用每兵一个 Collider。
- 当前选择显示地面选中环，并持续显示“攻方 · 已选 120 / 存活 1,024”。选中环与图鉴半径圈语义不同，避免混淆。
- 普通框选替换上一次选区；首版不附带编队快捷键、复杂增减选或永久小队系统。
- 保留“整军团指挥”的明确入口。框空时进入 0 选中并禁用指令，不静默退回整军团下令。
- 切换军团时清除上一个局部选区，并清楚显示新作用范围；已下达的旧命令继续有效，不因取消选择而撤销。
- 鼠标选区与已下达命令分离：换选区后，上一批士兵仍执行自己的命令。
- UI 拖动、镜头操作、移动目标选点与框选互斥；鼠标穿过 UI 不产生战场误指令。
- 再战、回布阵、换场景后失效旧选择；死亡成员从活跃选区剔除。

### 2.3 四种动作的建议语义（待确认）

| 动作 | 首版建议 |
|---|---|
| 移动 | 仅选中士兵前往指定有效区域；沿用现有移动的交战语义，不夹带修改整个游戏的移动规则 |
| 攻击 | 仅选中士兵主动接敌，优先复用现有进攻行为；本轮不额外引入点名集火或全新攻击移动模式 |
| 撤退 | 仅选中士兵撤向其所属军团既有出生／后方锚点；未选成员保留原命令 |
| 待命 | 建议为停止主动行军和追击，保留必要分离／避让，并允许攻击范围内自卫；不是关闭模拟或完全停火 |

如果“待命”希望严格等于停火，需要单独确认；不能只把现有“防守”按钮换名字，就假定语义一致。

### 2.4 技术落点与限制

当前关键链路按 teamId 下令并共享阵营级导航目标。直接把选中列表传给旧团队命令接口仍可能让全军团一起转向，因此需要一条真实的局部命令通道。

建议架构：

1. **成员选择**：GPU 侧根据相机投影、选框、teamId、存活状态生成选择掩码；异步回读计数，不每帧同步读回全部士兵坐标。
2. **稳定身份**：确认 agent 索引在本局生命周期内稳定；如会重排则增加映射。用本局代次防止旧回读结果或旧 ID 在再战后误用。
3. **命令快照**：提交命令时固化本次成员，不让之后改变选框反向改写旧命令成员。
4. **独立命令状态**：局部命令覆盖只写对应成员。敌我 teamId 保持不变，不能靠拆 teamId 或占用军团槽位伪造小队。
5. **导航分组**：多个不同目的地需要独立的命令组／导航通道；复用现有地形和流场机制，设置经测量确定的组预算、复用回收策略。不能一名士兵分配一张流场，也不能仍共享唯一军团目标。
6. **到达区域**：为成员提供有间距的临时到达位置，避免全部抢同一坐标；本轮不扩展完整战中阵型系统。目标和到达位置均需遵守地形与障碍规则。
7. **失败原子性**：非法坐标、不可达目标、组预算不足等应明确拒绝，保留旧命令，不半数更新后再失败，不偷偷覆写另一组。
8. **逐步验证**：先验证同军团两批士兵可各去不同位置，再接四种动作与完整 UI；关闭局部指挥时旧整军团路径保持可用。

这项属于体验补齐，但技术上不只是增加一个选择框。需要触及 GPU 命令消费、导航分组和运行时生命周期；先做隔离原型，不同时混入无关战斗规则改动。

### 2.5 验收

- 同屏跨双方框选，只选择当前军团；死亡与镜头后方单位不能误选。
- 1,024 人中选 120 人发令，未选 904 人的命令和路线不被改写。
- 同军团两组去不同地点，后发令不把前组拖走；取消选择不取消已下命令。
- 同一士兵被新命令覆盖、部分成员死亡、暂停／恢复、再战均无残留或越界。
- 选空不全军误动，拒绝目标不损坏旧路线，鼠标不穿透 UI。
- 先小规模正确性再默认 2,048 人体验与性能，不自动启动十万人压力试验；没有运行测试前不承诺性能数字。

## 3. 部署地图拖动与阵型缩放

### 3.1 先澄清色块的对象

截图当前每方仅有一个编成，所以一个色块看起来等同整个军团。但现有代码是一块对应一个编成。

**首版建议按色块拖动当前编成**：军团内有多个兵种编成时只改抓住的那块。整军团多个色块一起平移／缩放属于另一个操作范围，需明确确认，不默认一起改。

### 3.2 建议操作

- 抓色块内部：平移位置，保持人数、密度、宽深比。
- 选中后显示边／角手柄：拖单边调整该轴长度；拖角调整两轴，可用 Shift 锁定比例。
- 拖边／角时对侧边／角固定；按锁定比例缩放时由同一约束求解实际矩形，避免跳动。此规则在开发前最终确认。
- 鼠标操作即时预览，右侧数值跟随显示；键盘精确输入仍保留，并与拖拽使用同一数据模型。
- 一次按下到松开只形成一次可撤销修改。Esc 取消本次拖动，回到拖动前。
- 无需先进入“点击放置”模式才能拖动；旧点击放置与直接拖拽互斥，松手不能再触发一次点击放置。
- 只更新战前草稿，不自动保存方案，也不重建正在运行的战斗。

### 3.3 固定人数下的联动关系

令 N 为人数，W 为战术正面宽度，D 为纵深：

```
面积 = W × D
密度 = N / (W × D)
宽深比 = W / D
```

因此：扩大色块会降低密度，缩小会提高密度；拉成长条会改变宽深比。不能在固定人数和固定面积下任意指定另一套密度。

**当前坐标约定：X 是纵深，Z 是正面宽度。** 地图横向拉伸主要改 D，竖向拉伸主要改 W；不能把屏幕矩形宽高直接当成战术宽深比。

截图示例：N=1,024、密度=0.4、宽深比=2.2，对应面积约 2,560 平方米、正面宽约 75.05 米、纵深约 34.11 米。等比例把面积扩大一倍，人数不变，则密度降到 0.2，宽深比仍为 2.2。

这些是当前公式的推导，不是此次测得的士兵实际间距。

### 3.4 校验与提交

- 拖动使用临时预览状态，不每帧调用会写撤销记录的 Draft.Set，不每帧重建 GPU 实例。
- 移动保留抓取点偏移；使用地图实际内容区域投影，而非整个带边栏面板。侧栏展开、窗口缩放、鼠标离开面板或失去焦点时不得跳位／残留拖拽。
- 校验完整占地，不只校验中心：边界、障碍、地形、既有重叠规则和物理排布均检查。
- 既有同队混合重叠规则不擅自改成全面禁止；密度与拥挤风险可单独提示。
- 非法位置／尺寸显示红色预览及原因，松手不提交，恢复上一个合法状态。系统不能偷偷改人数来塞进矩形。
- 参数超出允许区间时限制手柄实际位置，并显示限制原因；不能视觉矩形一套、数值被静默钳制成另一套。
- 手工占地与自动密度推导必须有单一真值。拖拽提交需明确处理旧手工模式，不允许尺寸覆盖仍生效但面板显示另一套密度。
- 有未提交或非法数值输入时先明确处理，不在开始拖动时无声丢弃文本。
- 合法松手后写一次草稿，继续走已有校验、应用、保存、撤销链路。

### 3.5 验收

移动不改人数／密度／比例；缩放不改人数或模型大小；鼠标尺寸与数值互转一致；单次撤销完整恢复；非法拖动不损坏草稿；多编成对象不误改；720p 与 1080p 均可用；真实开战部署与地图占地一致。

## 4. 角色半径、可视预览与拥挤排查

### 4.1 不先认定“半径太小”

需要区分：模型视觉尺寸、单位占地／分离半径、布阵初始间距、运动中的拥堵与分离行为。

小角色看起来堆叠可能来自半径与模型不匹配，也可能是初始密度、目标过度汇聚、分离力度／更新节奏、动画外扩或阴影层次。只在接敌时聚团，与开局静止就重叠，不是同一类问题。

现有代码确实已有 agentRadius，但它主要进入 GPU 群体分离等计算，不是给每个士兵添加 Unity 刚体碰撞球。增大它不保证“绝不重叠”，也不能把它当作攻击距离或完整武器／身体外轮廓。

### 4.2 图鉴显示与保存

建议新增“角色占地半径（米）”：

- 显示官方值、当前编辑值和来源；可调整、恢复官方值。
- 同时显示直径，明确半径不是模型缩放。
- 沿用现有保存全局流程，不改原始 ScriptableObject。
- 预览即时使用待编辑值；保存后按现有下次进入战场的边界生效，不在战斗中突然膨胀现有士兵。
- 战场存在方案局部覆盖时保留既有“局部 > 全局 > 官方”的解析顺序。
- 图鉴以模板 ID 生效，不因模型外观相同就批量改其他历史变体；验收必须确认战场引用的确是被修改的模板。
- 旧保存文件缺少半径字段时使用官方值；新字段追加，不能重排既有枚举／索引或改旧键名。

当前可调字段表只接战斗和移动配置，半径实际在 FlockingConfig。实现时需补齐该配置的读取、运行时复制、覆盖应用、GPU 参数更新与资源释放，不能只加一个不会生效的滑块。

### 4.3 模型预览中的真实范围

- 在模型脚下增加独立的半径圆环与可选淡色占地区域，标明 R 与直径。
- 使用实际单位根位置及同一世界尺度，不拿模型包围盒中心或当前假阴影大小代替半径。
- 圆环随预览旋转和透视自然变化，缩放时模型与圈同步；默认取景同时考虑模型和圆环，保留重置视角。
- 编辑半径只改变圈，不改变模型本身大小。现有阴影继续作为视觉阴影，不宣称它是占地边界。
- 图鉴内嵌预览与放大预览使用相同的待编辑／生效值，不能一个显示官方半径，一个显示全局半径。

### 4.4 半径和阵型密度需要联动约束

两名士兵的理想中心间距至少要考虑 r1+r2，并根据实际排布留余量。相同半径 r、理想方格且无抖动时，1/(2r)^2 可作初步密度参考；它不是包含阵列取整、抖动、不同兵种和地形后的最终安全保证。

地图缩小阵型时，应使用实际解析后的半径、生成行列、间距及抖动来判断是否排得开。调大半径可能使原来合法的密集布阵不再适用，必须提示，而非让单位一出生就重叠。

半径还会影响导航通行、近战接敌距离、邻域查询及部分弹道查询。支持范围应按现有查询能力和地图尺度确定，不先做可任意放大的滑块。增大后尤其要验证是否“身体隔开了，却够不到攻击距离”。

### 4.5 源码中值得专项核对的点

`AgentDataCommon.hlsl` 中，接触排斥的 bodyDistance 使用 agentRadius × 水平缩放，而另一段分离 minDistance 直接使用半径和。该差异值得核对其设计约定和真实角色缩放，但**当前没有证据证明它就是用户所见拥挤的根因**。

此外，部分现有密度与地形清距检查读取配置半径。应审查半径、模型缩放、物理分离、地形清距与 UI 圆环是否采用一致或明确区分的单位约定，避免仅在预览中画对。

### 4.6 验收

- 图鉴待编辑值、保存值、重新进入战场后的实际生效值与圆环一致。
- 同一模板的近景静止、行军、接敌三个阶段分别观察；不同体型角色比较。
- 记录中心间距／穿插程度，而非只凭远景截图猜测。
- 调半径不改模型大小、伤害、兵种归属或原始资源；非默认缩放也检查。
- 恢复官方值、取消编辑、旧方案兼容正确；不会出现图鉴改了但战场仍用另一模板的假通过。
- 半径调整后仍能通过合理通道、正常近战命中，不出现明显抖动或性能退化。

## 5. 建议分轮实施，不一次把三项混在一起

### 第 A 轮：半径透明化与拥挤定位

先接通已有半径显示、预览及生效链路，复现指定兵种的静止／运动／交战表现。只对证实的问题作定向调整，不批量把所有角色半径放大。

### 第 B 轮：部署地图直接操作

先拖动位置，再做尺寸手柄、参数联动、合法性与撤销；不增加新阵型种类，不新增地形编辑。

### 第 C 轮：军团内局部指挥

先建立可独立导航的局部命令原型，再做框选、高亮、四种命令和完整回归。保持旧整军团操作回退路径；不引入联盟、永久编队、复杂战术 AI。

每轮分别记录改动、真人操作效果、正确性与性能证据。是否产生新包需明确决定；不能覆盖现役 `Builds/CaptureDefault-20261006-37/`。新手引导不自动恢复实施。
