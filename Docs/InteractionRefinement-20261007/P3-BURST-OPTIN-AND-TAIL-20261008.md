**结论先行：** Burst 后备路径已在 Editor 中做到“默认关闭、可由进程参数显式开启、托管开关优先”，并通过了真实编译失败、禁用/强同步、150 项回归验证。冷启动的长卡顿在有/无 Burst 的对照中都存在，不是 Burst 引起的；战斗中的 30–46ms 尾部帧主要落在求解与车道后处理上。**本轮未启用 Burst 默认值，未出包，未提交，P3/P9/Player/AOT/人工验收均未关闭。**

## 1. 默认关闭接入（已在 Editor 临时候选中验证）
- 默认无参数：不分配 Burst 工作区、不做探测，全部走托管（回归 150/150 通过）。
- `--war-sandbox-nav-burst`：显式开启；未就绪时仍走托管，就绪后才用 Burst。
- `--war-sandbox-nav-managed`：与开启参数同时出现时托管优先。
- 实际编译器禁用、强同步：拒绝分配并走托管，0 工作区/0 探测。
- 真实编译失败：Burst 报出 `BC1021`（指向 `TerrainNavigationSolveJob`），60 秒超时后转为 Unavailable，托管输出与原始结果逐位一致，无后续探测，工作区 1 创建 1 释放。

限制：这些验证是 Editor 测试，不是 Player/AOT，也不是人工 UI 的失败恢复。异常仍是释放并抛出，不等于优雅恢复界面。
