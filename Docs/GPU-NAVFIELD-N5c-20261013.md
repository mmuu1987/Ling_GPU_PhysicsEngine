# 导航 C · N5c：后排不再挤进已到达的方阵（2026-10-13）

## 结论

- **平原效果明显。** 开启后，到达后的方阵不再被后排压成一条细带：
  - 纵深 34.4 → **45.5 m**；
  - 占用格子 1989 → **2687**（+35%）；
  - 单格人数 p95 7 → **6**。
- **山口基本持平，略有代价。** 过岭人数 555 → 455（单次运行），卡住人数 581 → 554，到目标的中位距离 152.4 → 151.7 m。
- **帧耗时没有变化。** 平原 11.77 ms，山口 12.69 ms。
- **新开关 `gpuNavArrivalFollow` 默认关闭，没有删除任何代码。** 不开 GPU 导航的着色器变体完全不受影响。
- 测试 **159/159** 通过（原有 158 + 新增 1），编译 0 错误。

## 原因

- 先到的人停下后方向变成 0。
- 后排普通行军没有跟车距离：跟车距离原来只在交战和前沿区生效。所以后排一路顶上去，分离力把方阵越压越扁。
- 拥堵等待（等 1.1–2.0 秒后重试）只是暂停推挤，并不能阻止推挤。

## 做法

- **到达区（按队计算）：**
  - 阵线目标：到达区深度 = 方阵估算纵深（存活人数 × 0.6 m² / 阵线宽度）× 1.5；
  - 点目标：到达区深度 = 圆形方阵半径 × 1.5；
  - 动态追击类目标：没有到达区。
- **在到达区内：** 普通行军（不在交战或前沿区）改用已有的跟车距离规则，前面有人就停在他身后，不再往里顶。
- **保持不变：** 侧向溢出和拥堵等待照旧，所以后排仍能向两侧铺开。
- **改动文件：**
  - `AgentDataCommon.hlsl`：记录每个人到目标的距离，新增到达区判断。
  - `AgentCombatSimulation.compute`：两处 kernel 各加一个分支，只在 GPU 导航 + 地形变体里编译。
  - `GpuNavField.Line.cs`：计算到达区并上传。
  - `RuntimeFlowConfig.cs`：新增两个字段 `gpuNavArrivalFollow`（关）和 `gpuNavArrivalZoneScale`（1.5）。
  - 管理器同步、测试、探针参数 `arrival`。
- **备份：** `outputs/Round6/n5c_bak`。

## 已知问题

1. **平原末尾约 860 人仍处于"移动"状态，原来约 480 人。** 这些是到达区边缘的后排：前面有人就停，有空隙再往前挪一点。这些人不会再压进方阵，但看起来会有零星的小步挪动。
2. **山口过岭人数少了约 100。** 出口离目标线很近，刚出山口的人也落在到达区里，开始保持车距。这只是一次运行的结果，有一定噪声。
3. **可调参数：** 把 `gpuNavArrivalZoneScale` 从 1.5 调到 1.0，可以缩小到达区，代价是松散程度也会降低。
