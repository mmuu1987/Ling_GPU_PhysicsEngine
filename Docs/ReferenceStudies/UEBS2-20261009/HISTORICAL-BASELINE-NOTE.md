# 历史性能口径更正

查阅我们工程现有 Assets/Game/PerformanceBaseline.md 后，确认之前对话如果让人理解成“整个项目只测过2048人”，是不准确的。2048是近期局部命令冷编译/功能诊断规模，不是底座历史最大规模。

- 2026-07-27历史编辑器记录：总20万人57.1ms（约18FPS），压力档，存在grid overflow；不是当前版本性能结论。
- 2026-09-28旧FarLod包，参考机i7-7700/GTX1060 3GB/D3D11/720p，正常Present的两组100k交战31.07/30.59FPS，特定镜头及时间窗口。
- 2026-09-30另一个已记录GUID的实际用户包：100k交战29.43/29.70FPS；两窗均<30。不能把它等同于当前37包或P12候选。
- Docs/CURRENT_DELIVERY.md指出现役37默认2048；高人数、真人、V1等验证边界仍须按对应包判断。

因此现在应先归档和复用旧证据、确认代码/资产/渲染方法差异，再补当前容量对照；不把已做过的历史工作说成不存在，也不将旧成绩外推为新版本20万人承诺。
