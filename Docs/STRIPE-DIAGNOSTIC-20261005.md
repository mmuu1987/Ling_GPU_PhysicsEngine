# 前进攻击平行条带 · 只读诊断（2026-10-05）

## 结论
在当前32版源场景的绿色战场、默认2048人（每方1024）Editor Play Mode中复现了用户描述：攻方初始方阵在约15—30秒推进后形成多条平行人流和明显空带。
这是GPU模拟坐标本身发生的聚集，不只是相机剔除或模型漏画。0/5/15/30秒的双方单位均各有1024个非Dead记录；图表读取完整agentBuffer，而不是可见实例列表。

当前运行配置：256×256流场格，每格2米，原点(-256,-256)，覆盖512×512米，与战场尺寸一致；地形GPU导航已分配。不能把本次现象归为“流场覆盖范围太小”。网格精度和导向方式仍需区别看待。

## 已定位的成带机制与尚未闭环的部分
1. `Assets/MassEngine/Terrain/TerrainNavigationGrid.cs`，CreateFlowField约155—210行：多源Dijkstra，每格只输出一个8邻居下一步方向。路径代价使用真实地表边长；因此微地形与离散最短路可能让多个区域共用路径。
2. `Assets/MassEngine/Core/Shaders/AgentDataCommon.hlsl`，SampleFlowDirection约682—714行：地形分支将direction取sign得到下一格，再用 `nextCenter - position.xz` 作为实际单位导航方向。即使格内方向是正X，也会向下一格中心的Z坐标施加横向吸引。这是明确存在的格心吸附机制，不是仅凭截图猜测。
3. `Assets/MassEngine/Terrain/TerrainNavigationRuntime.cs`：当前场景使用CPU地形流场并上传；旧平面 `AgentRuntimeFlow.compute` 的分区质心逻辑不是这里实际生成方向的路径，不能因配置sectorCount=5就宣称条带来自“五分区”。
4. 5秒真实流场中，攻方脚下1024个采样有962个方向为(1,0)，62个为右下对角。此时单位距所在Z格中心线的平均距离由初始0.524米降至0.218米；落在中心线±0.25米内的比例由30.8%升至72.1%，支持早期格心聚集。
5. 15—30秒出现比单格更宽的条带和空带。不能把所有较宽条带的宽度直接等同2米格宽；离散路径汇聚、真实地形代价和避让／密度反馈之间的贡献，尚未做修改后的隔离A/B确认。现在可确认复现与格心吸附机制，不宣称已证明唯一根因或修复有效。
