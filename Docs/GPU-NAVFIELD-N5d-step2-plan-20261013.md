## 最终收尾盘点：GPU 导航还依赖旧路径的什么

| 旧路径部分 | GPU 导航是否依赖 | 能否删除 |
|---|---|---|
| 粗导航网格（4 m 可走区域） | **依赖**：GPU 细格从它生成 | 不能 |
| 敌人密度缓冲（runtime flow 密度） | **依赖**：追击目标就是它 | 不能 |
| CPU 团队方向场（Dijkstra，后台线程） | 只做**兜底**：新命令后 GPU 场算好之前约 0.1–0.3 秒、显卡不支持计算着色器时 | 删了会导致这段时间士兵原地不动 |
| CPU 局部命令方向场 | **局部攻击命令一直走 CPU**（N5a 定的：每 0.25 秒换目标，GPU 种子来不及） | 不能 |

**收益很小。** 11 万人追击时，CPU 方向场每 90 秒累计只花约 34 ms，而且在后台线程，不占主线程。

**建议：**
- 不做整块删除，改成"某队的 GPU 场有效时，跳过这队的 CPU 方向场计算"；
- GPU 场无效时照常算，兜底保留；
- 这算行为不变的小优化，可以放在第 2 步之后。
