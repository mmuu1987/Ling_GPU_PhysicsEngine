# 条带原因进一步隔离 · 2026-10-05

## 范围
用户再次要求检查。本轮复用上一轮已核SHA的默认32绿色场景GPU读回数据，在本地做固定流场轨迹回放。没有启动新Unity进程、没有修改远程游戏源码／shader／参数，也未出新包。
这不是完整游戏内A/B，不能作为修复有效或障碍安全验收。

## 方法
相同1024个攻方初始位置，2×2对照：
- 导向场：统一正X方向／实测第5秒的team0完整流场。
- 采样后推进方式：朝下一格中心／直接沿该格方向。

保持256²格、2米cell、origin(-256,-256)。用3.3米/秒的常速点轨迹、dt=.02、1500步（名义30秒、99米路程预算）。不模拟速度惯性、避让、碰撞、地形高度速度变化、目标接敌或动态场更新。方向为零时停下；所有采样均检查仍处于网格范围内。

## 结果
| 对照 | 中央Z=-30…30米内，30个2米分箱中的空箱数 | 距Z格中心≤0.25米比例 |
|---|---:|---:|
| 统一正X＋格心 | 0 | 100% |
| 统一正X＋直接方向 | 0 | 30.8%（初始比例不变） |
| 实测流场＋格心 | 12 | 100% |
| 实测流场＋直接方向 | 12 | 16.9% |

将积分步长减半／加倍、总路程预算保持99米后，以上空箱数均保持不变。详见sensitivity.json。空箱数指预设固定分箱，不等于12条独立连续空带。

图中：统一方向时格心导向会排出更整齐的2米行，但没有形成同样的较宽空带；实测流场无论是否走格心都出现宽空带。点可能重合，这是未加入碰撞／分离的机制隔离模型，并不代表实际角色可以互穿。

## 比上轮更明确的认识
- 实测导航场本身已经包含能让不同出发位置汇入同一路线的方向分布。仅去掉格心吸附，并不足以阻止本次固定场回放中的宽空带。
- 格心吸附是另一层机制，会让单位更严格集中在网格中心线。两层需要区分，不能把“修格心”当完整修复。
- 不加入避让也能生成宽空带，说明避让不是这种分带发生的必要条件；不代表它在完整游戏中没有影响。
- 既有TerrainNavigationGrid只保留单个8邻居下一步、按真实地表边长选最短路，是下一处应检查和改进的生成环节。微地形代价、等价路线选择、目标分布各自的贡献，本轮尚未单独隔离。
- 512²覆盖范围不足仍不是本次复现的解释；本轮没有测试提高分辨率能改善多少，不能承诺简单加密网格会解决。

## 后续修正建议（尚未实施）
需要同时考虑开阔区域流场方向的连续性／多条近似等价路线，以及减少不必要的格心吸附。真实障碍附近保留合法邻接和扫掠检查；不能直接把当前离散向量插值后上线，以免切角、穿墙或进入禁行区域。
改动应在独立候选里做完整GPU模拟A/B：相同初始队伍、实际动态流场、避让、开阔推进、转向和绕障碍，然后再判断修复效果。
