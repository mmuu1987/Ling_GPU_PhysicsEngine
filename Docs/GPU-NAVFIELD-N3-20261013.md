# 导航 C · N3 报告（2026-10-13）

## 结论

N3 完成。士兵现在可以沿 GPU 距离场的梯度（eikonal，圆形波前）行进。四项验收：

| 验收项 | 结果 |
|---|---|
| 与现行为一致（追击战 11 万人） | ✅ 接敌 9.2 s（基线 8.9 s），存活曲线、帧时间基本一致 |
| 条纹消失 | ✅ 山口行军中，移动士兵朝向贴着 45° 整数倍（±3°）的比例从 **17.1% 降到 4.1%**（随机朝向约 13.3%）；前 10 秒从 33.6% 降到 1.9% |
| ForestHills 山口可通行 | ✅ 约 115 秒时越过山脊 **289 人**（同条件仅 CPU：31 人；原基线：40 人），中位距离 171 m（CPU：246 m） |
| 关闭 LaneApproach 也能工作 | ✅ 上面的山口数据就是在 LaneApproach 全关的条件下测的 |

全部改动都在默认关闭的开关后面，没有删除任何东西。不打开开关时，游戏行为和以前完全一样。

1. 勾选 `gpuNavField`（建场）；
2. 勾选 `gpuNavSteering`（士兵用 GPU 场转向）；

建议在森林丘陵对山口（x=-230, z=455）下移动命令，看队伍形态。

## 改了什么

**N3a 距离度量**
- GPU kernel 新增 eikonal 更新：8 邻域加 8 个三角形，`_NavMetric` 选择度量。图距离模式保留，原来的逐位测试改为显式使用图模式。
- CPU 种子在 eikonal 模式下改用 Fast Marching（同一个堆，弹出一个格子后，对邻居做完整的三角形更新）。
- 每帧末尾保证每队的最新结果都在 A 缓冲区，供士兵采样。
- 有效性追踪：目标一变就失效，种子上传后才重新生效（`ValidMask`）。

**N3b 士兵采样**
- `AgentDataCommon.hlsl` 新增 `GpuNavSteer`，只在 `MASS_TERRAIN_ENABLED && MASS_GPU_NAV` 下编译：
  - 四个格心做双线性插值求梯度，然后检查一个细格长度的线段是否畅通；
  - 不畅通时，选下降最快的邻居格心（同样检查线段）；
  - 返回 false 时交回 CPU 流场。返回 false 的情况：该队无效、所在格不可达、点目标最后两个粗格（8 m 内）。
- 战斗着色器新增本地关键字 `MASS_GPU_NAV`，只在战斗派发期间打开，派发后立即关闭（kernel 测试共用这个资源）。
- Orchestrator 给主 kernel 和本地命令 kernel 绑定缓冲区。
- `RuntimeFlowConfig.gpuNavSteering`，默认 false。
- 远程补丁 `outputs/Round6/patch_n3.py`，备份在 `outputs/Round6/n3_bak/`。

## 测试

- EditMode `GpuNavFieldTests` 加 `Terrain`：**133/133 通过**。新增 3 个用例：
  - 开阔地点源：距离误差最大 2.2%；方向误差 p95 为 **3.1°**（图距离为 20.1°）；
  - GPU 与 CPU 各迭代 200 轮：相对误差最大 1.6e-7，有 61/2304 个格子只差 1 ulp（sqrt 舍入）；
  - Fast Marching 种子与 CPU 收敛结果 **逐位相同**；种子之后 GPU 再算 3 轮，最大变化 9e-8。

## Play 实测（森林丘陵）

| 场景 | 帧时间均值 | 接敌 / 越脊 | 条纹指标 |
|---|---|---|---|
| 追击 11 万，GPU 转向 | 55.9 ms | 接敌 9.2 s | 0.158 |
| 追击 11 万，基线 | 55.7 ms | 接敌 8.9 s | 0.159 |
| 山口 2 万，GPU 转向，Lane 关 | 12.6 ms | 116 s 越脊 289 | **0.041** |
| 山口 2 万，仅 CPU，Lane 关 | 14.4 ms | 114 s 越脊 31 | 0.171 |

追击战两军正面对冲，主要靠追敌方向，所以条纹指标在这里区分不出差别；它的作用是验证行为一致。

GPU 开销：每轮约 0.042 ms；种子作业约 77 ms，在后台线程运行。

## 已知问题和注意

1. 山口入口在后期会拥堵：116 秒时有 1195 人速度低于 0.1 m/s。原因是所有人都走最短路径挤到同一个口子，拥挤成本要到 N4 才加入。
2. 点目标最后 8 m 仍由 CPU 处理，以保证精确到达和停止半径。
3. 战斗着色器变体数量翻倍，第一次导入会慢一些。
4. 探针里的"逐位比较"和"收敛"两项诊断拿的是图距离参考，eikonal 模式下必然显示不一致，可以忽略。
5. 只有前 32 个队伍支持 GPU 转向，其余队伍回退到 CPU。
