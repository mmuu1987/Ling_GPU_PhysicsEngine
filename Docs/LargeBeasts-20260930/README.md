## 不只改模型缩放

已看真实源码：分离只扫邻近1圈，近战以中心距离判断。本轮只在**新私有场景/config**配置：
- 各自Simulation.cellSize=9m，覆盖两半径之和；world240×240、每格64槽。旧场景网格不动。
- 大型和骑士对照均使用宽松手动阵型（狼约41×41m、公牛45×45m），源人数8/32，保存测试12/32；不把大兽塞进小人默认密度。
- 双方近战中心距离分别4.65m/5.05m，确保骑士也能触及大型单位。不是全局武器变长，不等于牙齿/角/剑刃实形状命中。
- 大型速度/Move参考速度2.5，HP300、伤害30，作者攻击周期；骑士对照速度/参考3，其余沿用。只是可交互展示配置，不是兵种配平结论或新玩法。
- 私有镜头调整以看全稀疏编队，仍可拉近/旋转；不重做镜头系统。

没有改战斗/分离/寻敌/渲染核心或公共烘焙器。既有ModelTrialSmoke只增加可配置初始/保存人数与可选预检查钩子，默认仍64/96、钩子空；旧斧盾回归验证兼容。新增LargeBeastBuilder、CaseRouter和Probe是本批准备/验证辅助。

## 素材准备与精度

动物原FBX无UV，使用多个纯色材质。准备器把原颜色写入私有线性色板（4×4，最多16色），按材质边界必要时复制顶点并保留原顶点映射；不是套用旧骑士纹理。狼原3796→3815顶点、公牛4732→4736；每帧按映射核对原导入件位置。

沿用前批单位缩放准备方法处理100倍层级：自有顶点/法线/bindposes、单位变换、作者原动作采样。最终尺寸和原点在**第一次Half编码前**整理，再走原2.5mm门禁。原件→准备后两模型1373948个顶点帧对照，最大约0.00657mm（门禁0.25mm）；VAT层同样逐帧检查通过。

狼Idle/Walk/Attack/Death；公牛Idle/Walk/Attack_Headbutt/Death。24FPS采样，Low预算2000、每模型纹理预算32MiB；实际位置+法线纹理约14.672/24.688MiB，不是总显存。最终96张GPU动作/LOD结果+32张准备后独立位置参考；参考共用shader/UV/法线，非原材质独立渲染。

### 蜘蛛为什么暂缓

- 初版大狼VAT误差约2.826mm，保留失败；把最终尺寸/居中前移到准备层后，狼、公牛通过，仍用2.5mm门禁。
- 7m蜘蛛Attack仍约3.782mm；尝试精确预备高度、禁用重复落地后约3.780mm，仍拒绝。没有调高容差、删掉攻击动作或声称修好。
- 原生未量化BakeMesh与独立LBS的只读对照最大约0.00197mm，权重和误差很小；单独Half测试不能完整解释其VAT误差。定位在后续VAT编码/采样链，**具体原因未定，不武断归因于Half位宽**。
- Spider准备/配方和失败回执保留做诊断；没有成功Generated输出，也不在正式目录。用户目标是2–3种，本轮交付其中两种可靠四足。
