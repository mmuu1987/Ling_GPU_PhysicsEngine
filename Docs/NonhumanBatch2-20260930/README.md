## 蜘蛛限时复查的结论

本轮只做了一次限定的只读完整Bake/LBS/Half定点诊断：**在准备后模型最终坐标中直接烘焙，最大误差2.388563mm≤2.5mm**。最坏点的实际Half编码值与FloatToHalf/HalfToFloat预测一致（Death9帧1668顶点）；不是蒙皮解算错误，也不能继续用此前单轴测试猜原因。

结合源码，旧配方把已经完成居中/落地的非零ScalePivot又声明成待处理sizeRoot；通用流程会先清掉这个offset，在另一坐标范围量化，再补回offset。这与已预处理的输入职责重复，额外量化误差无法靠恢复平移消除。

新LargeSpider04：保留原准备Prefab、网格、动作、尺寸；**sizeRootPath为空、targetHeight取真实已准备高度、groundBindFeet=false**，只表明“输入已为单位缩放、最终原点，不再整理一次”。公共烘焙器/管线/容差完全没改。新产物全部动作、LOD和位置检查通过；旧失败仍是失败，不改回执。

这也约束新恐龙配方：静态200倍导入层级与尺寸/原点先在新准备资产内消解，原件→准备层按24FPS采样核对，准备层→VAT按实际四槽时间窗逐帧核对。前层恐龙最大约0.0041mm≤0.25mm；不把采样点一致说成所有连续时刻无损。
