# 操作与保存指南

适用GUID：`01c3512de1eb461c8923cbe7054ea84a`。这是Windows单机键鼠候选版，不要求安装Unity编辑器；最低硬件尚未定型。建议从1280×720、小规模预设开始，不把参考机当最低配置保证。

## 1. 正常启动与首局

1. 将原ZIP**完整解压到可写目录**，保留EXE、Data、DLL和子目录的相对位置，不在压缩包内直接运行，不只复制EXE。
2. 双击 `Start-WarSandbox.cmd`。原脚本开启1280×720窗口并为本次运行创建独立日志；不需要测量脚本或探针参数。
3. 默认进入512人准备战场。可直接按 **Enter** 开战；**Space** 暂停/继续。界面也有对应按钮。
4. 查看结算中的胜者、胜因及各军团初始/存活/损失；可原样重开、返回布阵改方案或由底部战场目录换场。
5. 僵持时可选“结束本局（不判胜负）”，这不算任何一方获胜。退出前留意未保存修改提示。

首次体验请先自行探索，记录从启动至首局结束的墙钟用时与求助情况；不能把自动对局时间算作首次上手时间。

## 2. 镜头与指挥

鼠标放在战场区域，避开UI：

| 操作 | 作用 |
|---|---|
| 按住右键 + WASD | 自由镜头移动；右键拖动观察方向 |
| 滚轮 | 缩放 |
| 右侧军团按钮 / 1～9 | 选择实际存在的军团（数字按列表顺序） |
| A / H / R | 所选军团进攻 / 防守 / 撤退 |
| M，再点击可通行地面 | 替换移动目标 |
| M，再Shift+点击地面 | 追加航点；没有已有路线则建立新路线 |
| Esc | 取消尚未确认的移动选点，原命令/路线保留；不是通用退出键 |
| F / F3 | 跟随所选军团 / 战场全景 |
| Enter | 准备阶段开始；终局按界面重新开战 |
| Space | 暂停 / 继续 |

快捷键在输入框编辑时被屏蔽；先结束文字输入。右键/中键/Alt/滚轮镜头操作期间避免同时下指挥命令，防止把A误解为移动与进攻同时执行。

**暂停中的移动命令有区别**：点击替换目标会继续运行；已有移动路线时Shift追加保持暂停；没有路线时Shift会建立新移动命令并继续运行。界面选点提示会说明当前情况。非法/不可达落点被拒绝后原命令保留，可重选或取消。

命令影响整个军团，不是独立操控其中近战/远程小队。防守不是无敌；撤退不保证安全脱战。

## 3. 配兵、布阵与方案

在准备阶段进入配兵/布阵，按界面修改编成、人数、位置等，检查部署脚印及错误提示后**应用**。不合法时根据原因修改，不要反复开战绕过校验。

保存使用新的名字，例如 `V1_Manual_日期_A`，避免覆盖已有重要方案。建议另存A→改变一项另存B→载入A并应用→开战；退出程序后重新进入对应战场，再载入自己的方案。载入方案是恢复战前配置，**不是恢复进行中的战斗、伤亡、录像或GPU快照**。

- 内置模板只读，个人保存不覆盖默认预设。
- 跨战场方案先进入对应战场；不能假定载入会自动换图。
- 原样重开恢复本局应用后的战前兵力，不从死亡状态继续。
- 未保存的草稿不跨退出/换场保留。
- 缺失/损坏/版本不兼容的方案出现错误时保留原文件与提示，不手改格式版本，不通过删除全部存档“修复”。

## 4. 声音与本机数据

底部设置可调整音效音量/静音；打开设置暂停当前交战，关闭后恢复此前状态。保存设置后退出并重启，可检查是否恢复；若无声，依次检查游戏静音/音量、Windows音量混合器、输出设备。

普通游戏使用当前Windows账户目录：

```text
%USERPROFILE%\AppData\LocalLow\DefaultCompany\Ling_GPU_PhysicsEngine\WarSandboxPlans
%USERPROFILE%\AppData\LocalLow\DefaultCompany\Ling_GPU_PhysicsEngine\WarSandboxSettings.json
```

迁移或排错前，关闭游戏并备份上述自己的方案目录与设置文件。多份解压包可能共享该保存位置，换包不等于隔离存档。不要分享整个用户目录，也不要删除既有重要方案。兼容性以界面校验为准，不承诺所有未来版本都能无损读取当前方案。

## 5. 战场与负载

| 预设 | 初始总兵力 | 体验重点 |
|---|---:|---|
| 开阔对冲 | 512 | 初次操作、自然结算 |
| 山地绕行 | 384 | 高低差、通行限制、军团指挥 |
| 中央据点 | 512 | 占领/争夺和胜因 |
| 三方混编 | 768 | 多军团指挥与完整统计 |
| 标准规模 | 100,000 | 大规模观察，明显更高负载 |

人工收尾以四个小预设为主，**不要求再次运行性能采样或长时压力测试**。当前100k实测边界见版本说明。严重卡顿时停止本次观察并记录，不同时启动多个游戏/Unity/浏览器采样任务。

## 6. 反馈与启动问题

每次由正常脚本启动，包目录 `Feedback/Player-*.log` 新建独立日志。记录本次对应的文件名；若直接运行EXE，通常日志位于上述用户数据根目录的 `Player.log`，可能被后续运行轮替，退出后及时复制保存。

反馈至少包含：包GUID、预设/初始人数、操作步骤、期望/实际、是否重复出现、设备/分辨率、截图或短视频，以及本次日志。用附带的人工记录表另存填写；日志或截图含个人路径、用户名时，可在保留原件的前提下脱敏后分享。

无法启动：先确认完整解压与可写目录，保留报错与日志；不要下载不明DLL、关闭系统安全防护或覆盖正在核对的旧包。更改过说明/填写记录/生成Feedback是正常使用变化；复核出厂字节用保留的原ZIP，不为通过全文件校验清空玩家反馈。
