# M7.3 普通窗口帧率验证

2026-09-28。**参考机100k默认档交战实测13.97/13.74 FPS，未达到产品约30 FPS目标。** 普通窗口采样已完成，GPU计时取得有效数据；M7.3性能预算仍未关闭。山地错峰与12轮稳定性证据继续有效，见 [上一轮记录](M7.3山地错峰与长时复测.md)。

## 包、环境与方法

- 使用已有 `Builds/M73Desktop/WarSandbox.exe`，GUID `a8af4df1af524145ba1f3ef8257d28ba`，未重建或修改玩法代码。参考机i7-7700 / 16GiB RAM / GTX1060 3GB，驱动560.94，Unity6000.3.14f1、D3D11、Development。
- 1280×720、原场景镜头与LOD中心、完整实际uGUI、关闭垂直同步、不限帧。正常相机/Present路径，无验证RenderTexture、StandardRequest或逐帧GPU强制回读。截图在采样窗外生成。
- ABBA：100k平面→384人山地→山地→平面。准备预热3秒、采样8秒；正常1倍速交战至约20模拟秒后采12真实秒，不含结算，不裁剪长帧。
- 用户确认继续前台采样后启动。Windows初始窗口可见、未最小化、位于前台；8窗全部采样帧均保持焦点，渲染回调数与帧数相符。仅完成初始激活，不在失焦后反复抢占前台。
- 平均FPS用总帧数/总墙钟时长计算，即1000/平均帧时。GPU为FrameTiming记录的整帧时间，并按时间戳去重；不当作某一个kernel的成本。

## 性能判断与下一步

后续已完成绘制/计算诊断和首发远景优化；新包完整前台ABBA补测为31.07/30.59 FPS，参考机720p既定镜头/时段的平均目标已确认，转人工试玩。本文保留优化前失败预算及当时分析，不代表当前包状态；最新证据与边界见 [GPU拆分与远景预算](M7.3GPU拆分与远景预算.md)。

100k两次交战GPU平均68.828/70.046ms，与墙钟71.571/72.792ms接近；准备阶段GPU也已59.130～60.250ms。结合采样期间一次 `nvidia-smi` 快照（P0、GPU99%、1885MHz、76°C、显存1026/3072MiB），下一项应优先拆分GPU负载。该快照不是全程监控，也没有分离绘制、空间网格、LOD分类、战斗及弹道的成本，不能据此指定某个kernel为瓶颈。

当前证据仅覆盖指定镜头、参考机和短时采样窗，不能与历史100k编辑器32.8ms直接作同条件回归。也不能把上一轮强制同步离屏81～82ms与本轮约72ms的差值当作引擎优化收益；两者执行方法不同。

下一项仍属M7.3：在独立诊断包中固定100k人数、相机和同一战场，分离准备期常驻GPU计算与VAT绘制，再定位交战新增成本；诊断关闭某项的结果不得当作完整游戏帧率。取得原因后只处理阻塞默认档的成本，再复测完整正常路径。保持约30 FPS目标与原人数，不以降低人数、隐藏HUD或改统计门槛完成验收。

M6人工地形试玩、非开发者首次体验、听感及V1整体放行仍待独立确认。更长内存趋势和既有表现瑕疵不因此升级为本次主线。

- 本轮没有C#/shader或配置改动，无需重跑完整Unity测试；沿用上一轮416/416 EditMode、85/85 GPU PlayMode和12轮/四自然对局通过结果。原始包与证据均保留。

