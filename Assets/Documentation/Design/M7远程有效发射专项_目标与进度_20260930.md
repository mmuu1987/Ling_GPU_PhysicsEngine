# M7 远程有效发射专项：目标与进度

日期：2026-09-30。用户授权长程独立推进，今晚不参与测试；人工观感留待用户次日确认。

## 唯一目标

解决“大量远程发射动作却缺少可见有效弹体、前排停射导致后排难以参战”的专项问题。
让射程内有条件参战的后排真正发射；弹道受阻者有限侧移寻找射界；只有真实发射正常仍不清楚时才改显示。
本轮暂缓 V1 收尾，不做全军团战术/阵形/射程重构。

## 决策顺序

- [x] A. 最小复现与计数：攻击/请求 → 实际生成 → GPU 在飞 → 命中/友军/地形/超时 → 容量拒绝，分清主因。
- [x] B. 修复被实测确认的发射链阻塞；不把已经修好的4096快照尾部问题重新当成根因。
- [x] C. 后排抛射：保留直射；使用有界的越顶弹道和真实友军/地形碰撞，无法通过就判受阻，不默认穿透。
- [x] D. 受阻后的有限侧移：只作用远程战术，稳定方向/重试节奏、有界距离，不能让所有人左右摆动或破坏已认可的拥堵等待。
- [x] E. 只有数据支持时调整视觉；不添加无伤害对应的假弹幕，不用无限拖尾伪装发射量。
- [x] F. 定向回归 → 新目录独立构建 → 小场景真实玩家程序验证 → 单独候选包与交接。

## 验收门槛

1. 在小规模、实际角色半径/高度、多排友军的可通行场景中，记录前后排的真实发射/在飞/命中，不只看动作状态。
2. 原本无障碍的远程不应无故停止或明显降低发射；直射、暂停、死亡、重开、切场和近战保持兼容。
3. 能越顶的抛射不被无谓拦截；无法安全发射的情况应抑制持续空播攻击并尝试有限侧移或等待。
4. 不穿透地形，不把友军误伤引入默认规则；角色尺度进入净空判断，未来巨型单位不在本轮全面验收范围。
5. 接受移动/Hold/撤退等新命令后，不被旧侧移或等待拖住；不因额外决策偷加攻击预算。
6. 如果确认池容量/回收是主因，必须有小规模真实复现与回归，保留未消费请求/生命周期/异步代次安全；不无条件全GPU重写。
7. 候选程序与打包运行文件身份可核验，旧UI/拥堵/运动候选完整保留；不以自动结果代替用户视觉认可或V1签收。

## 明日人工检查与边界

1. 原标准100k场景中，射程内后排是否更常真出箭；不要把射程外深排也算作应当同时发射。
