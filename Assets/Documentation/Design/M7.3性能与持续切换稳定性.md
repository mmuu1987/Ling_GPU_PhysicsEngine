# M7.3 性能与持续切换稳定性（原采样方案）

此文保留最初采样方案。已执行的结果、非零Windows进程内存计数修正见 [M7.3参考机采样与持续切换](M7.3参考机采样与持续切换.md)；后续动态求解分摊与12轮复测见 [M7.3山地错峰与长时复测](M7.3山地错峰与长时复测.md)。当前状态以结果文档与 `ROADMAP.md` 为准。

2026-09-27，承接 M7.2。此项建立现役首发预设的参考机采样和持续重开/换场证据，不把旧编辑器帧率直接沿用到新独立包。

## 范围与入口

`Builds/M73Stability/Start-WarSandbox.cmd` 继续使用 M7.1 的五个场景、M7.2 的全军团结算和声音设置。
构建菜单 `MassEngine/Launch Presets/Build M7.3 Windows`；原 M7.1/M7.2 包保留。
验证只在显式 `--terrain-cycle` 下运行，不改变正常启动和玩家设置。

本轮不修改预设人数、GPU kernel 或数据契约。若发现主路径资源释放缺陷，先修复并复验；纯表现问题继续留待后续。

## 性能采样方法

- 参考机 i7-7700、GTX 1060 3GB，驱动 560.94；Unity 6000.3.14f1、D3D11、Development 独立包。
- 1280×720，作者场景镜头，LOD 中心随镜头，包含实际战斗 HUD 和底部导航；关闭垂直同步，不限帧。
- A 为现役标准档 100000 人平面，B 为 384 人山地。按 A→B→B→A 运行，分别报告，不能据不同人数相减计算地形开销。
- 每次新场景预热 3 秒，准备阶段采样 8 秒；正常开战至 20 模拟秒，再采样 12 真实秒。检查战斗仍在运行，不含结算，不裁剪长帧。
- 自动窗口隐藏，逐帧显式提交完整 URP StandardRequest，并等待 1 像素回读完成。因此记录的是含同步成本的 CPU+GPU 串行整帧耗时，**不是桌面 Present 帧率**。
- CSV 记录整帧、渲染提交、GPU 完成等待、流场求解增量；提交/等待是主线程墙钟区间，不冒称单个 GPU kernel 时间。FrameTiming 没有有效样本时报告不可用。
- 统计平均、p50/p95/p99/最大值；区分包含 CPU 流场求解的帧与其他帧。截图在采样窗外生成。

自动报告与预算结论已另写入上述结果文档；不能用同步离屏耗时直接宣称桌面 30 FPS 达标或不达标。

## 持续重开与切换方法

五个入口按开阔512→山地384→据点512→三方768→平面100k轮换四轮。首轮预热资源缓存，后三轮比较。
每次通过 UI 打开布阵并应用独立副本，开战后两次原样重开，再开战并手动结束，最后从结算返回目录。
总计划 20 次配兵副本应用、40 次完整 GPU 重建、20 次退出释放。

- 每次重开检查旧 GPU 缓冲已释放、新缓冲已分配、满兵、无旧命令/胜负和正确地形提供者。
- 每次退出检查 Manager、地形 GPU、运行时 Scenario/Unit/Spawn 副本都销毁，声音服务只保留一个。
- 每轮在相同目录状态先记录自然回收前数据，再显式 UnloadUnusedAssets + GC 后记录保留量，两者分开，不用强制回收后的数字冒充正常运行峰值。
- 同时记录 Unity 已用/预留、托管已用/堆、图形驱动分配估计、进程私有字节/工作集，以及对象、网格、材质、RT、配兵资产和音频对象数量。
- 预热后配兵资产不增长，音频固定为1个服务/1个音源/5段音效。小型内部缓存余量：对象8、网格2、材质4、RT2；已用内存余量：Unity8MiB、托管4MiB、图形估计16MiB、进程私有64MiB。
- 这些余量用于发现明显持续累积，不能证明无限时间或任意硬件下绝不泄漏；保留逐轮原始值供判断趋势。

两阶段都使用未存在的独立设置路径，只在进程内静音，不保存偏好；不访问配兵保存/载入界面，不改写玩家方案。

## 复现

构建执行 `MassEngine.Game.Editor.WarSandboxLaunchPresetsBuilder.BuildM73Windows`。
在独立进程顺序运行，避免两个测试竞争 GPU：

```text
WarSandbox.exe -screen-fullscreen 0 -screen-width 1280 -screen-height 720 --terrain-cycle --terrain-cycle-phase=stability --terrain-cycle-output=<新的绝对目录> --war-sandbox-settings-file=<未存在的独立绝对文件路径> -logFile <日志>
WarSandbox.exe -screen-fullscreen 0 -screen-width 1280 -screen-height 720 --terrain-cycle --terrain-cycle-phase=release-performance --terrain-cycle-output=<另一新的绝对目录> --war-sandbox-settings-file=<未存在的独立绝对文件路径> -logFile <日志>
```

输出目录、设置路径和玩家 persistentDataPath 必须隔离；正常启动不执行测试。不加 `-nographics`，后台启动使用 `-WindowStyle Hidden`。
首发内容的 64 份场景/配置哈希、原 M7.2 试玩行为保持独立检查。执行状态与证据见上述结果文档。
