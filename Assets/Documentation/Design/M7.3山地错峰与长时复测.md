# M7.3 山地错峰与长时复测

2026-09-27～28。接续 [上一轮参考机采样](M7.3参考机采样与持续切换.md) 的已确认问题：384 人山地交战每隔一段时间将三个 CPU 流场求解集中在同一帧，求解帧约 67～73ms。

后续普通窗口采样已完成，100k交战约13.7～14.0 FPS，约30 FPS目标未达成；见 [普通窗口帧率验证](M7.3普通窗口帧率验证.md)。下文保留本轮同步离屏/稳定性数据，不混用测量方法。

## 改动

`TerrainNavigationRuntime` 在当帧收取所有已完成 GPU 回读，把非零密度格转换为各军团独立的稀疏目标快照；随后按军团轮转，每个 Manager Tick 最多消费一张动态流场。
不能直接把原生回读请求留到后续帧再读取：Unity 完成的回读数据只在有限帧窗口内有效。新测试实际跨帧等待，验证快照仍可用。

待处理快照不会被新动态请求覆盖，轮转避免低 ID 军团持续抢占；显式移动/防守取消旧请求和排队目标，显式目标保持即时求解。等待期间继续使用上一张有效流场。
限制的是每帧动态求解数量，不保证单次 Dijkstra 的绝对毫秒上限；新增 `TerrainMaxDynamicQueueWaitMilliseconds` 记录就绪后排队等待，复核长帧改善与延迟代价。
不改 GPU kernel、数据布局、地形可达性计算或原兵力配方。

稳定性探针增加 `--terrain-cycle-rounds=12`（允许4～30），保持原有资源/内存容差，扩展为60次布阵副本应用、120次重开、60次切场。
若某轮超过内存容差，继续记录剩余轮次用于判断趋势，最终验证仍失败，不以跳过错误冒充通过。
