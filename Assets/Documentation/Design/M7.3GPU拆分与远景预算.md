# M7.3 GPU 拆分与远景预算

2026-09-28：100k主要开销定位到单位绘制，首发Male远景VAT由994顶点/2096三角形降至 **98顶点/234三角形**，近/中景保留。接续补跑同包完整前台ABBA，两组100k交战为 **31.07 FPS、30.59 FPS**，本参考机720p既定镜头/窗口内的平均约30 FPS目标达成，性能确认可收口并转人工试玩。**M7/V1仍未放行**。旧desktop-1失焦失败及其29.08 FPS窗口完整保留，不删低值或拼接样本。

**焦点限制**：诊断报告的 Unity `Application.isFocused` 每帧为 true，但启动 Win32 记录为 false，运行中的独立 OS 观察发现另一进程在前台。保留全部原始记录，`final-audit.json` 明确 `foregroundVerified=false`、`eligibleForProductFpsAcceptance=false`。这轮用于负载定位，不补充正式普通窗口验收。

证据：`Logs/M73GpuBreakdown/run-1` 的 10 CSV、20 份 LOD 绘制快照、10 PNG；`audit_breakdown.py` 已在内容迁移前独立复算并核对当时 64 份原内容。进程退出 0，内部流程通过不消除上述外部焦点限制。

## 内容调整

- `VatLodReducer.CreateFarVariant` 复用原始全分辨率 VAT 采样，按既有聚类算法生成最多 128 顶点的远景网格和配套位置/法线纹理，实际输出 98 顶点。四段片段窗口、帧数、播放率不变。
- 新 `Assets/Game/M73RenderBudget/MaleFar128.asset` 共享原近景资源，将原 Low 资源显式保留为 Mid；只有 Far 是新子资产。近/中景 GPU 对拍逐像素一致。
- 新渲染配置保留原材质和阴影参数。只把五个首发预设中 10 个 Male 单位的 `renderConfig` 指向新配置；同一单位也作为方案模板，模板 ID / revision、人数、出生点、战斗参数均不变。
- 未运行 `Prepare` 或重建首发配方。原 110k 场景、Game/Settings、VAT_Data 和旧包保留。
- 292 份迁移前源文件逐一核验，仅 10 份单位文件发生变化，去掉该引用行后字节一致；其余 282 份不变。旧 64 文件基线不覆盖，新基线独立存于 `Logs/M73FarLod/preset-content-hashes.json`。

Far 有明确减面代价，放大对拍轮廓 IoU 最低 0.643、均值 0.700；不能宣称远景画面完全相同。实际只在既有远景距离使用，近/中景不变。最终观感仍随人工试玩确认，不以自动像素门代签。
