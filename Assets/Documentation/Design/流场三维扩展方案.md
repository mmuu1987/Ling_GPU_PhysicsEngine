# 流场三维扩展方案

## 状态

2026-09-26：M5 已经用户验收关闭；复杂地形按 2026-09-14 重排后的 M6 执行。
本文件保留技术预研；当前实现约定见 [M6.1连续地表原型](M6.1连续地表原型.md)。
范围与验收以 [产品总策划案](../../../GAME_DESIGN.md) 和 [路线图](../../../ROADMAP.md) 为准。
当前执行顺序是 M6 复杂地形 -> M7 交付；Mod 与联机暂缓，经营系统不做。

M6 先完成连续地表的高低起伏、坡地、山谷/峡谷、狭窄通道和不可通行区域，而非仅增加平面矩形墙。
当前 MassEngine 的位置、空间哈希、密度图、障碍和流场仍以 XZ 平面为核心；具体契约改动在原型验证后确定，
不直接把二维纹理扩大成全局 XYZ 体素场，也不预先把多层或飞行所需字段塞进现有布局。

## 推荐路线

M6 优先评估第 1 项，并结合第 3 项验证通行；第 2、4 项保留为未排期参考，不要求逐项执行。
下面列出候选路线，优先保持现有 GPU 数据通道：

1. **地形表面投影**：流场仍为 XZ 网格，采样地形高度与法线，把移动方向投影到表面。适合连续坡地，是首选实现。
2. **分层流场 + Portal**：桥梁、楼层和洞穴各自维护二维网格，通过坡道、楼梯、门洞等 portal 连接。Agent 增加 `layerId`，跨层时切换流场。
3. **战略流场 + 局部行为**：流场只给长程方向，分离、密度压力和局部避障负责短程修正；不要要求一张流场解决所有碰撞。
4. **局部稀疏 3D 场**：仅为飞行单位或特殊体积区域分配 brick/hash-grid，避免全场三维体素的立方级内存成本。

## 分阶段实施

### A. 连续复杂地表（M6 必做）

- 增加高度/法线采样源。
- 移动速度投影到地形切平面。
- 定义坡度上限、陡坡/悬崖禁行、通道连通性与不可达目标反馈，验证多军团绕行与单位贴地。
- 优先保留 XZ 空间哈希；核对高低差下的邻域查询、近战距离、射程及弹道/地形阻挡，不能沿用错误的平面命中规则。
- 部署脚印、点击/命令落点、标记、镜头与模拟使用同一地表定义；具体数据源先做原型比较。
- 地形关联与版本接入本地方案，缺失/不兼容时无损拒绝；重开恢复同一战前方案并正确重建资源。
- 用至少一个复杂地形代表局验证完整对战，同时回归原平面场景；记录目标规模下的显存和帧时。

### B. 多层支持（V1 非目标，未排期参考）

- Agent、空间哈希键和流场索引加入 `layerId`。
- 定义 portal 图和跨层状态。
- 每层独立生成流场，CPU 或低频 GPU pass 选择下一 portal。

### C. 飞行单位（V1 非目标，未排期参考）

- 单独建立稀疏 3D 导航模块，不污染地面单位的紧凑数据布局。
- 先限定活动体积和最大高度，再评估 brick 尺寸与显存预算。

## 必须保持的契约

以下为实现时的验证要求，不代表本次文档修改已经变更或验证引擎契约。

- 地面单位的热路径不能因未启用的三维功能增加明显带宽。
- `teamId` 和 `UnitTypeGpuSettings` 继续是身份与参数的唯一来源。
- 新增维度后，C#/HLSL stride、buffer 所有权和双缓冲交换仍须有自动测试。
- 先以真实地图和目标 Agent 数量做显存/帧时预算，再选择分层或稀疏 3D；不采用全局稠密 XYZ 流场。
