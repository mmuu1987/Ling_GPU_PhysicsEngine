# M6.3 地形闭环验收

> 2026-09-27；承接 M6.2 三军山地入口。最终独立包两进程自动闭环、离屏性能补测通过；人工试玩单独签收。

## 交付与验证范围

独立包：`Builds/M63TerrainValidation/Start-TerrainBattle.cmd`。正常启动沿用山地目录、384 人默认编成及原始 11 万人平面战场；验证组件仅在显式命令行参数下运行。

`WarSandboxTerrainCycle` 复用实际 uGUI 回调及 RuntimeDeployment、PlanStore、SceneSession。A/B 方案第一编成分别为 80/48 人，其余五编成各 64 人，总计 400/368 人。兵种战斗参数不变，普通速度下由默认命令作战，不写 HP、不注入胜负。

- 拒绝悬崖上的部署脚印，检查原 GPU 世界未替换，再用 Undo 恢复。
- 通过布阵界面改变人数、保存两个方案，通过列表/确认/应用恢复完整编成；逐字段比较稳定模板身份和存档。
- Seed 进程跑 A 的自然结算，Reload 进程跑 B 的自然结算；两个进程都加载并应用 A/B，分别完成原样重开、再次开战。
- Seed 回执保存进程身份、构建 GUID、两份方案 SHA-256。Reload 必须是不同进程、相同构建且文件字节未变，不能重新生成方案伪装载入。
- 山地 → 原始 110k 平面（开战/重开）→ 默认山地，检查默认人数、地形提供者、GPU 释放、运行时 Scenario/Unit/Spawn 销毁与源资产 JSON 不变。
- 每个验证目录必须新建，方案目录与用户实际方案及输出目录不重叠；不删除或改写玩家存档。

## 性能口径

参考机：i7-7700、GTX 1060 3GB、D3D11、Unity 6000.3.14f1，Development 独立程序。1280×720 完整相机离屏渲染，关闭垂直同步，不限制帧率。窗口隐藏，屏幕覆盖 UI 不包含在目标纹理中，因此属于可复现的自动基线，不等同于用户桌面实玩帧率。

山地为默认 384 人，平面为原始 110000 人，分别报告，不能计算成同人数地形开销比。固定镜头：山地 `(-95,235,-280)` 看向 `(-75,24,0)`；平面 `(0,260,-220)` 看向 `(0,0,40)`，LOD 中心随相机。

准备阶段预热 3 秒、采样 8 秒；开战至 20 模拟秒后采样 12 真实秒。输出逐帧 CSV、平均/p50/p95/p99/最大帧时，不裁剪 CPU 求流场造成的长帧。GPU FrameTiming 仅为补充，无数据时明确为不可用。

`performance-v2/` 首轮虽然每帧确实提交了完整绘制，但隐藏窗口没有 Present 节流，110k 开战样本出现 p50 1.465ms、p95 355.672ms 的 GPU 队列集中等待。因此它只保留为提交吞吐诊断，不能用来宣传平滑帧时。最终补测在每帧绘制后回读 1 像素并等待 GPU 完成，测 CPU+GPU 串行的离屏整帧耗时（含同步成本），与普通桌面帧率分别报告。

地形流场记录已完成求解数、Dijkstra 累计耗时与最长单次求解，计时不包含 `SetData` 上传。共享地形 GPU 字节数精确计入高度、通行格及导航掩码；Unity 图形驱动分配估计另列，不冒充显卡物理容量或整个进程的精确显存。

山地交战窗口完成102次流场，CPU求解总计2060.536ms，平均20.201ms/次；该世界生命周期最长单次44.000ms。每0.35秒附近的多军团CPU重建会造成长帧，平均值掩盖了卡顿，M7参考机预算需要跟进。本轮不改求解架构，也不把它判为“山地已满足正式默认档”。

共享地形缓冲 **788484字节（0.752MiB）**，平面0；Unity图形驱动分配估计山地约161.18MiB、平面约182.79MiB。它们包含不同单位数和场景资源，不能相减当作地形开销。旧M5.3的110k开发包约56.8/69.8ms、旧100k编辑器32.8ms均有不同测量前提；本轮未重新验收桌面30FPS。

## 复现

先用 Unity 执行 `MassEngine.Game.Editor.WarSandboxTerrainPlayableBuilder.BuildM63Windows`。不要重新执行 `Prepare`，它会拒绝覆盖已有地形资产。

在不同独立进程顺序运行：

```text
TerrainBattle.exe --terrain-cycle --terrain-cycle-phase=seed --terrain-cycle-output=<新的绝对输出目录> --terrain-cycle-plans=<新的绝对方案目录>
TerrainBattle.exe --terrain-cycle --terrain-cycle-phase=reload --terrain-cycle-output=<另一新的绝对输出目录> --terrain-cycle-plans=<上一步方案目录>
TerrainBattle.exe --terrain-cycle --terrain-cycle-phase=performance --terrain-cycle-output=<新的绝对性能目录>
```

PowerShell 自动运行使用 `Start-Process -WindowStyle Hidden`，Unity 批测不加 `-nographics`。阶段通过时进程退出 0，完整报告 `completed/passed` 均为 true；中途进度报告不能冒充结果。Seed/Reload 间不能重建程序，否则构建 GUID 校验会拒绝载入。

## 出口与后续

本轮自动闭环不替代人工地形试玩或 V1 签收。人工关注上下坡/窄口路线是否易读、鼠标落点与镜头、战前布阵和战后重开；已有 M5 签收不重开。M7 再收口首发四个预设、第三/第四军团结算 UI、反馈与设置及正式参考机预算。

原有寻敌半径 25m 受 4 格上限限制的提示、局部密集格溢出和画面精修沿用主线优先原则：未阻断本次命令/结算的项目记录到后续，不为少量编成表现改 GPU 数据契约。
