
# Stage6 游戏制作与架构方案 v0.1

## 1. 游戏目标定位

我们的目标不是传统 RTS，而是做一个 **大规模战争模拟沙盒**。

核心体验应该是：

- 玩家能快速摆出两军或多军阵容。
- 能配置兵种、数量、阵型、出生区、目标方向、AI 行为。
- 点击开始后，看成千上万单位自动推进、接敌、攻击、死亡。
- 玩家主要乐趣来自“设计战场、观察结果、调整参数、再模拟”。
- 后期可以加入 RTS 指挥、第一/第三人称附身、战役关卡、录像回放。

一句话定位：

**一个以 GPU 海量单位模拟为核心的战争沙盒编辑器 + 战斗观赏器。**

## 2. 对 UEBS2 的玩法拆解

UEBS2 的强点主要不是复杂战术，而是这几个层次：

- **规模冲击**：非常多的单位同屏，形成视觉奇观。
- **沙盒自由度**：玩家可以自由放置军队、数量和组合。
- **阵营对抗**：不同单位属性、数量、位置导致结果差异。
- **可观看性**：玩家像导演一样观察大规模战场。
- **轻指挥**：RTS 控制、单位附身让玩家能干预战斗。
- **内容扩展**：战役、玩家自定义内容、不同题材单位。

所以我们不应该一开始追求复杂 RTS 经济、建筑、科技树。  
更应该优先把“战场搭建 + 大规模自动战斗 + 结果反馈”做扎实。

## 3. 我们当前已具备的基础

Stage6 目前已经有几个很关键的基础能力：

- GPU Instancing + VAT 动画渲染。
- 攻击方 / 防守方双阵营。
- 双方可用不同 mesh、material、VAT profile。
- LOD 分级渲染。
- Spatial Hash 用于邻近查询、分离、寻敌。
- HP、攻击距离、攻击间隔、伤害、死亡状态。
- 攻击方和防守方各自可使用固定或动态流场。
- 防守方可站防，也可沿流场进攻。
- 基础场景已经能跑通战斗闭环。

这说明我们已经跨过了最难的“海量单位能动、能打、能显示”阶段。  
下一阶段应该从“功能堆叠”转向“产品结构”。

## 4. 核心游戏循环

建议主循环设计成：

1. **创建战场**
   - 选择地图。
   - 添加阵营。
   - 选择兵种。
   - 设置数量、出生区域、阵型、目标方向。
   - 设置固定流场或动态目标。

2. **配置规则**
   - 单位血量、速度、攻击距离、伤害、攻击间隔。
   - 阵营行为：进攻、防守、追击、守点、沿路径推进。
   - 战斗规则：是否自动开始、是否允许重新寻敌、是否允许越界。

3. **运行模拟**
   - 开始、暂停、重置。
   - 调整速度。
   - 切换镜头。
   - 观察战线推进、包围、死亡、胜负。

4. **查看结果**
   - 存活数量。
   - 击杀数量。
   - 阵营剩余血量。
   - 战斗时间。
   - 热点区域、死亡区域、交战区域。

5. **调整并复盘**
   - 修改数量或参数。
   - 换阵型或流场。
   - 再跑一局。

## 5. 游戏内容模块

建议游戏内容拆成这些制作模块：

### 阵营模块

阵营是最高层组织单位的概念。

每个阵营应该有：

- 阵营名。
- 阵营颜色。
- 阵营 ID。
- 默认敌对关系。
- 默认出生区域。
- 默认目标区域。
- 默认行为模式。

初期可以只有攻击方、防守方。  
后期可以扩展成红、蓝、绿、多国混战。

### 兵种模块

兵种是未来扩展性的核心。

每个兵种应该配置：

- 模型 / 材质 / VAT 动画。
- HP。
- 移动速度。
- 攻击距离。
- 攻击伤害。
- 攻击间隔。
- 碰撞半径。
- 分离强度。
- 动画状态映射。
- 行为偏好。

初期兵种可以很少：

- 近战步兵。
- 重装步兵。
- 快速轻兵。
- 远程单位，后续。
- 巨型单位，后续。

### Spawn 模块

Spawn 不是单纯随机点，应该成为可编辑战术布局。

需要支持：

- 矩形出生区。
- 圆形出生区。
- 阵列阵型。
- 横排阵型。
- 方阵。
- 散兵。
- 多波次出生，后续。

Stage6 现在已有 attacker/defender spawn center/size，这是很好的起点。

### 行为模块

行为决定单位怎么参与战斗。

建议先定义几种清晰模式：

- **进攻模式**：沿目标方向或流场推进，遇敌攻击。
- **守点模式**：围绕 home position 防守，敌人进入范围才反击。
- **追击模式**：发现敌人后允许离开原位追击。
- **流场推进模式**：单位主要听从流场，接敌后短暂攻击。
- **混合模式**：远处走流场，近处按目标寻敌。

你现在提到的“防守方站着防守”和“防守方沿流场进攻”，就应该正式归入行为模块。

### 导航模块

导航不应该只是“路径”，而是战场导演工具。

需要支持：

- 手绘流场。
- 动态流场。
- 多目标流场。
- 阵营独立流场。
- 局部阻挡区。
- 战场边界。
- 可视化预览。

这对我们的项目非常关键，因为大规模单位不适合每个单位跑传统 NavMesh pathfinding。  
流场是正确方向。

### 战斗模块

战斗模块负责单位之间的规则。

初期保持简单：

- 目标搜索。
- 攻击距离判断。
- 攻击冷却。
- 伤害结算。
- 死亡状态。
- 死亡动画停帧。

后期可以加：

- 护甲。
- 暴击。
- 阵营克制。
- 范围伤害。
- 远程弹道。
- 士气。
- 击退。
- 友军阻挡。

### 观战模块

这种游戏“看”本身就是核心玩法。

建议设计：

- 自由镜头。
- 战场俯视镜头。
- 跟随单位。
- 阵营统计 UI。
- 热力图。
- LOD / 性能显示。
- 慢动作。
- 暂停观察。
- 一键重播，后期。

## 6. 游戏架构方案

从产品架构上，我建议分成 5 层。

### 第一层：Scenario 战场配置层

负责描述“一场战斗是什么”。

包含：

- 地图配置。
- 阵营列表。
- 兵种列表。
- Spawn 布局。
- 行为模式。
- 流场配置。
- 胜负规则。

这层应该是以后保存关卡、读取关卡、做编辑器的核心。

### 第二层：Simulation 模拟层

负责“单位怎么动、怎么找敌、怎么打”。

包含：

- Agent 数据。
- Team 数据。
- HP / 目标 / 冷却。
- Spatial Hash。
- Collision / Separation。
- Combat。
- Flow Field Navigation。

这一层是我们目前 GPU Compute 的核心。

### 第三层：Presentation 表现层

负责“单位怎么显示”。

包含：

- Mesh。
- Material。
- VAT Profile。
- LOD。
- Billboard。
- 死亡动画。
- 阵营颜色。
- 特效，后续。

这层应该和模拟层解耦。  
同一个兵种逻辑，可以换不同模型表现。

### 第四层：Control 控制层

负责玩家如何干预。

包含：

- Start / Pause / Reset。
- 时间倍率。
- RTS 拖选，后续。
- 指定目标点，后续。
- 附身单位，后续。
- 编辑器操作。

初期可以只做战斗开关和参数调试。

### 第五层：Telemetry 反馈层

负责告诉玩家发生了什么。

包含：

- 存活数量。
- 死亡数量。
- 击杀数。
- DPS。
- 战斗时间。
- 阵营胜负。
- 性能统计。
- 战场热力图。

这层很重要，因为大规模模拟如果没有统计反馈，玩家只能“看热闹”，很难形成可调试、可复盘的玩法。

## 7. Stage6 推荐制作重点

我建议 Stage6 的目标不是继续加更多功能，而是把系统整理成“可继续长大”的版本。

优先级如下：

1. **先做配置结构**
   - 阵营配置。
   - 兵种配置。
   - 渲染配置。
   - 流场配置。
   - Spawn 配置。

2. **再做战场 Scenario**
   - 一个场景可以保存一场战斗配置。
   - Manager 读取 Scenario 初始化。

3. **再做调试 UI**
   - 显示双方数量、死亡数、战斗状态。
   - 可以 Start / Stop / Reset。
   - 显示当前流场模式。

4. **最后扩展玩家操作**
   - RTS 选中。
   - 下达移动/攻击目标。
   - 镜头跟随单位。

## 8. 不建议现在做的东西

这些先别急：

- 复杂经济系统。
- 建筑系统。
- 科技树。
- 完整 RTS AI。
- 复杂装备系统。
- 多人联机。
- 太多兵种。
- 过早做剧情战役。

原因是它们会掩盖项目真正核心：**海量单位模拟是否好看、稳定、可配置、可扩展。**

## 9. 我建议的产品路线

### Stage6：架构整理版

目标：把现有功能整理成可配置、可维护架构。

交付标准：

- 双方战斗稳定。
- 配置清晰。
- Manager 不再臃肿。
- Compute 结构清晰。
- 能快速创建不同战斗测试。

### Stage7：沙盒编辑器版

目标：玩家能在场景里配置战斗。

内容：

- 阵营配置面板。
- 兵种选择。
- Spawn 区域可视化。
- 流场可视化。
- 战斗统计 UI。

### Stage8：玩法增强版

目标：从“模拟器”变成“可玩游戏”。

内容：

- RTS 指挥。
- 目标点命令。
- 单位选择。
- 战场时间控制。
- 胜负条件。
- 关卡保存/加载。

### Stage9：内容扩展版

目标：更多兵种、更丰富战场。

内容：

- 远程单位。
- 巨型单位。
- 范围伤害。
- 阵营克制。
- 多阵营混战。
- 地形阻挡。

## 10. 总结

我们现在最正确的方向是：

**先把 Stage6 做成“万人战争沙盒的稳定核心架构”，再谈玩法扩展。**

当前已经实现的 GPU 渲染、双阵营、LOD、VAT、流场、Spatial Hash、战斗死亡，已经足够支撑一个早期原型。  
下一步真正重要的是：把它变成可配置的游戏系统，而不是继续在一个 Manager 和一个 Compute Shader 里堆逻辑。
