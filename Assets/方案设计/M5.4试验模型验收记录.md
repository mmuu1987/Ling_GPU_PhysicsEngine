## 处理过的问题

1. tail 原 UV 范围 `(-1.655210,0.009740)`～`(2.460050,1.898570)`、wrap=Repeat。先测量实际范围，再离线采样整个矩形；顶点仅仿射变换，不 clamp/mod。极端输入仍拒绝。
2. 4096 带 mip 的文本 Texture2D.asset 达 178,958,010 字节，超过 GitHub 限制；改无损 PNG 后重新加载持久纹理再绑定材质，不降分辨率。
3. 生成器跨场景切换后重新读取持久资产，不依赖旧栈变量；并用新 Unity 进程构建检查落盘引用。
4. 删除路径仍可能被 AssetDatabase 记住，Baker 的只新建保护拒绝重用。改用全新 `M54TrialPlayable`，没有放宽覆盖保护；失败目录已清理。
5. Windows Mono 保留输入 `E:/`，GetFullPath 返回 `E:\`，探针误判绝对路径。仅归一化根路径分隔符，补 8 项测试；相对/根目录仍拒绝。
6. `Start-Process -Wait` 曾被常驻许可子进程拖住；后续 `Start-Process -PassThru` + `WaitForExit()` 仅等待 Unity 主进程并收退出码，不把许可服务当项目锁。

失败日志保留，修正都在制作/验证入口，不修改引擎核心。

## 复现

有图形设备、同工程串行、不加 `-nographics`：

```text
Unity.exe -batchmode -quit -projectPath <工作树> -executeMethod MassEngine.Game.Editor.WarSandboxModelTrialBuilder.Prepare
Unity.exe -batchmode -quit -projectPath <工作树> -executeMethod MassEngine.Game.Editor.WarSandboxModelTrialBuilder.BuildWindows
```

默认内容根 `Assets/Game/M54TrialPlayable`，可指定全新 `--model-trial-root=Assets/Game/M54Trial_<后缀>`；默认构建根 `Builds/M54Trial`，可指定 `--model-trial-build=<目录>`。

```text
ModelTrial.exe --model-trial-smoke --model-trial-phase=seed --model-trial-output=<新的绝对seed目录> --model-trial-plan-directory=<事先不存在的独立方案目录>
ModelTrial.exe --model-trial-smoke --model-trial-phase=reload --model-trial-output=<新的绝对reload目录> --model-trial-plan-directory=<同一方案目录>
```

两进程串行、同一构建；不混入旧 smoke/performance 参数。正常人工试玩不加这些参数。
