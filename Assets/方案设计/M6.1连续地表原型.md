# M6.1 连续地表原型与契约

2026-09-26：用户确认已运行文档中的 M5.4 试玩内容并可验收，M5 关闭，进入 M6.1。
本轮交付连续地表数据、可观察的高地/坡道/峡谷原型、CPU/GPU 一致性与目标规模预算。
完整军团导航、战斗和玩家布阵接入属于 M6.2，地形对局闭环属于 M6.3。

## 数据决定

- 单个 XZ 位置只有一个地面高度，单位使用米；不增加 Agent 字段，不改现役模拟 kernel。
- `TerrainSurfaceAsset` 保存稳定 ID、正整数内容版本、XZ 原点/尺寸、顶点行列数、世界 Y 高度、
  每格人工禁行标记和最大坡角。数组按 `z * width + x` 排列；宽高指顶点，通行格为 `(width-1)*(depth-1)`。
- 每格固定沿左下至右上对角线分成两个三角形；CPU 采样、HLSL 采样、可视网格用同一分割。
  法线取所在三角面法线，不用与网格不一致的双线性高度。正边界属于最后一格，越界/非有限查询拒绝。
- 一格任一三角面超过坡角上限，或有人工禁行标记，整格禁行。坡角取梯度模长，不按 X/Z 分别放行。
  最大坡角当前是地图统一值；以后兵种差异若成为主线需求再扩展参数。
- 从资产创建独立只读快照；上传一次共享的 `float` 高度顶点与 `uint` 通行格，不按军团复制。
  257×257、720×720m 时两块 GPU 数据为 526,340 字节（约 0.502 MiB），不含网格和探针工作缓冲。
  关闭地形的旧战场不创建这些资源、不增加采样 dispatch。
- 速度保持原 XZ 朝向，按面梯度提升到切平面，再归一至原速度模长；坡上不额外加速。
  本原型只验证采样和切向速度，未把运动探针称作可玩战斗。

## 战场与存档衔接

现有方案格式 1 已包含 `terrainId/terrainVersion`、战场内容版本、世界尺寸；本轮不升格式版本。
M6.2 绑定真实提供者时，必须同时核对 ID、版本、世界原点/尺寸、有效数据；失败无损拒绝，
不能由同名字符串冒充提供者、退回平地或移动玩家布阵。旧 `flat-ground@1` 继续走显式旧平面路径。
高度、禁行、坡角、尺寸或分辨率改变都要递增地形内容版本，并递增受影响战场内容版本。
地图数据由内置资产提供，存档不复制高度数组。运行时快照与 GPU 所有权在 M6.2 接入 Manager 生命周期。

## M6.2 实施边界

- 以通行格和保守的单位半径留白接入多军团路径；禁止对角切角、越陡坡和不可达时直线兜底。
- 布阵覆盖全部脚印；命令落点、点击、标记和镜头与模拟使用同一表面。
- 近战与射程采用世界空间距离；高地无隐含伤害加成。弹道用扫掠段检查地表，防止大步长穿地。
- 每帧积分与 LOD 轻路径都贴地；尸体沉降以死亡处地表为基准；平面回归不变。
- 本轮的格通行性不是完成的路径求解器；窄道拥挤、实际军团绕行与交战成本须另测。

## 验证与入口

预算目标：本地图共享采样缓冲低于1 MiB，地表网格低于4 MiB；110k查询的新增采样成本以0.5ms/步为原型预算。
独立程序固定1280×720、关闭VSync；隐藏窗口下每帧显式绘制到离屏纹理，避免Windows跳过窗口渲染。
100k和110k各做平面/地表/地表/平面ABBA；每轮暖机120帧、采360帧。
另做9组各64次dispatch并用一条回读同步，记录中位摊销时间。该数包含提交/驱动/同步，**不是纯GPU时间戳**。
观察程序绘制同一地表网格，两组只切采样kernel；不绘制或模拟十万士兵。完整军团成本只能在M6.2整合后确认。
离屏颜色/深度目标在两组间相同，不计入地形数据缓冲；帧时间不包含可见窗口呈现，不能对外当成游戏FPS。

菜单 `MassEngine/Terrain Prototype/Create M6.1 Scene` 创建独立新目录，存在则拒绝覆盖；
场景 `Assets/Game/M61TerrainPrototype/TerrainPrototype.unity`，构建后入口 `Builds/M61TerrainPrototype/Start-Terrain.cmd`。
以下命令在实现工作树执行，不加 `-nographics`，同工程串行：

```text
Unity.exe -batchmode -quit -projectPath E:/GitHub/_worktrees/WarSandboxBattlefieldRules -executeMethod MassEngine.Game.Editor.WarSandboxTerrainPrototypeBuilder.PrepareAndBuildWindows -logFile Logs/M61Validation/build.log
TerrainPrototype.exe -screen-fullscreen 0 -screen-width 1280 -screen-height 720 --terrain-benchmark --terrain-output=E:/GitHub/_worktrees/WarSandboxBattlefieldRules/Logs/M61Validation/player-recheck -logFile E:/GitHub/_worktrees/WarSandboxBattlefieldRules/Logs/M61Validation/player-recheck.log
```

自动预算只代表采样原型，不能据此宣称复杂地形完整战斗达到30 FPS。

## 2026-09-26 实测与结论

**M6.1 完成，采用连续地表共享网格采样路线进入 M6.2；不需要增加 Agent 字段或全局XYZ体素。**

- EditMode **346/346**、GPU PlayMode **57/57**，失败/跳过均0；13项新CPU测试和2项GPU/网格测试。
  证据 `Logs/M61Validation/editmode.xml`、`playmode.xml`，包括原平面战斗回归。
- Windows构建通过；诊断绘制修正后重新构建与运行均退出码0：`build-v3.log`、`player-v3.log`。
  这次修正只在独立诊断组件，不改已经通过的地表采样/网格/现役kernel；重新验证的是构建和实际GPU绘制/采样。
- 最终证据 **`Logs/M61Validation/player-v3/`**：`budget.json`、8份各360帧的CSV、8份同步批次CSV、`terrain.png`。
  Build GUID `1a1416d67f8147f6b81087635b2f7c8f`；独立程序不包含UnityEditor程序集。
- 设备：i7-7700、GTX1060 3GB（报告2965MB）、D3D11、Windows10、Unity6000.3.14f1、Development构建。
- 地形采样缓冲 **526,340字节 / 0.502 MiB**；地表顶点/索引缓冲 **3,422,236字节 / 3.264 MiB**。
  查询探针另占4.80MB（100k）/5.28MB（110k），不是每个战场都需要的生产缓冲。
- 65,536格中63,367格可通行，2,169格因坡度或人工标记禁行；中央坡道—高地—窄出口—峡谷连续可通行。
- CPU/GPU按固定随机查询抽查一致；真实MeshCollider的120个落点与采样高度一致；最终GPU图像有205,576个地表像素，
  非空且非错误材质。助手已查看图片。退出前地表缓冲、查询缓冲和离屏资源均释放。

### 失败分类与保留证据

首轮 `player/` 虽然采样和释放通过，但隐藏窗口跳过屏幕绘制，截图全黑，帧时无效，已附INVALID说明。
诊断工具改为显式离屏DrawMesh，并增加非空/非粉色检查；`player-v2/` 正确被图像检查拒绝。
原因为直接RenderTexture投影的Y翻转需要同步面剔除和读回方向处理，且应显式设置viewport。
修复只在诊断工具，未放宽图像门槛；`player-v3/` 通过。不是地表或战斗kernel缺陷。

M6.1无需重新人工签收M5。下一任务为M6.2可玩整合，重点先接提供者/版本与生命周期，再接贴地、通行与交战。
