# MassEngine 接力规则

本工作区由多个大模型连续维护。开始任何任务前，必须先阅读：

1. `PROJECT_HANDOFF.md`：当前架构、完成情况、未提交改动、风险和下一步。
2. `AI_CHANGELOG.md`：此前每轮实际改动与验证记录。
3. `git status --short`：区分用户改动、前序模型改动和本轮改动。

## 强制记录要求

- **每次代码、Shader、配置、场景或文档改动都必须记录。**完成一个逻辑批次后，立即在
  `AI_CHANGELOG.md` 末尾追加记录；不要等到整轮工作结束才凭记忆补写。
- 每条记录至少包含：日期、目标、修改文件、行为变化、验证结果、尚未验证项、下一步。
- 如果修改改变了当前里程碑、风险或下一步，同时更新 `PROJECT_HANDOFF.md`。
- `AI_CHANGELOG.md` 只追加，不删除或改写历史记录；发现旧记录错误时追加更正说明。
- 配置资产和场景中的数值可能是用户亲自调出的结果。没有明确证据时，不得恢复、覆盖或批量格式化。
- 不得为追求“干净工作区”而丢弃现有未提交改动。提交、推送、合并必须获得用户明确授权。

## 工程原则

- MassEngine 是通用 GPU 引擎层，Game 是 WarSandbox 产品层；游戏玩法不得反向侵入引擎核心。
- 大规模路径保持 GPU 驱动，避免给 10 万～40 万单位增加逐单位 CPU 更新或全局敌人扫描。
- `teamIdReadBuffer` 是阵营唯一事实来源；HP、伤害和位置继续遵循既有双缓冲契约。
- 修改 `UnitTypeGpuSettings` 或公共 HLSL 声明时，必须同步 C#/Shader 布局、绑定和测试。
- 可以参考 UEBS2 的数据流和行为设计，但不得复制或重新发布反编译源码。
